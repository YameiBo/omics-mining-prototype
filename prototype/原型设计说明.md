## 1. 界面上移出的设计说明

以下段落原先写在页面里（`.note` 区块 或 页面头 `.phead__d`），现已移除。它们解释的是**为什么这么设计**，
开发实现时不必照搬文案，但需要理解背后的约束。

> **v16 界面精简**：① 工作台「辅助功能」卡（术语表 / 无障碍说明 / 本期范围与排除项）已撤下，
> 内容见本文档 §7；② 全部**页面级介绍段落**（`.phead__d`）与配套的「介绍」折叠开关已移除 ——
> 界面只留标题，介绍性文字由本文档承担；③ 样本档案血缘图下方那条「这张图说明了什么」说明条已移除。

### 1.1 为什么必须靠样本 ID（原「样本档案」页）

同一个受试者的血清与肝组织是两管不同的物理材料：血清跑蛋白组、肝组织跑基因组与转录组。
三份数据分别落在不同项目、不同批次，文件层面没有任何共同字段——能把它们认成同一个人的
**只有样本 ID**。

血缘谱系在这里不只是谱系图：它标出了每条组学记录用的是哪一份衍生材料，这是复核
「这三份数据到底是不是同一个人」时要看的第一件事。

> 实现要点：跨组学关联的唯一键是 `样本 ID`，不是项目、不是文件名、不是批次。
> ID 映射（如 S068A → S068）必须是显式可审计的动作，不能静默归并。

### 1.2 与结果全景的呼应（原「基因档案」页）

> **v46 已撤**：这一节描述的「基因档案」页（样本档案页内第二个页签）整块撤除了，理由见 §38。
> 下面这段**保留作设计史**——它讲的是「历史沉淀 vs 本次运行」这两类数字为什么必须同源，
> 那条约束在撤掉这一页之后仍然成立（结果全景里的数字依旧要与样本档案、溯源记录对得上）。

17q12 区域的 HNF1B 在 8 例样本中检出 10 个变异、等级为致病，与「结果全景」里建议优先复核的
17q12 区域一致。档案页回答的是「这个基因历史上出现过什么」，结果全景页回答的是
「这一次运行得到了什么」。

> 实现要点：档案页（历史沉淀）与结果页（本次运行）是同一实体的两个时间维度，
> 两处数字必须对得上，不能有各自的数据源。

### 1.3 为什么要有项目这一层（原「项目」页）

同一份参考基因组与工具镜像会被多个课题复用，但数据、样本与运行记录必须严格隔离——
**项目就是这条隔离边界**。切换项目时，右栏运行历史与样本、数据集同步过滤，
避免把 A 课题的样本误配到 B 课题的流程上。

> 实现要点：项目是权限与数据的双重边界，不是「文件夹」。所有列表查询都要带上项目上下文。

### 1.4 样本与集合是两级结构（原「数据集」页）

一个样本可对应多个数据集（R1 / R2），一个集合则是一批数据集的有序列表。
流程运行时按集合做 fan-out——集合里有 6 个样本，流程就跑 6 个任务实例。

> 实现要点：样本是生物学单位，数据集是文件单位，集合是执行单位。三者不要合并成一张表。

### 1.5 日志是给谁看的（原「运行日志」页）

临床医生关心「我的任务跑到哪一步」，生信工程师关心「哪个镜像版本跑了这个流程」。
所以本页在工程师视图下会额外显示镜像版本与 jobId 列，医生视图下这两列隐藏。

> 实现要点：同一份日志数据，两种视图列不同 —— 视图差异是列的取舍，不是两套数据。

### 1.6 格式不支持时的行为（原「数据汇集」页右栏）

文件不在支持清单内时**不会直接终止**：系统会 ① 说明检测到的实际格式
② 列出系统支持的格式清单 ③ 给出自动转换 / 下载模板 / 重新上传三个动作。

> 实现要点：容错是「阻断 + 给可执行的下一步」，绝不是一个报错弹窗。

## 2. 阈值与口径：需与院方确认

这三个值仍是**待与院方确认**的业务口径，开发时应做成集中配置。
唯一来源在 `src/app.js` 的 `THRESHOLDS`，改一处全站生效；
`build.js` 有守卫校验它与静态 HTML 的展示值一致。

| 项 | 当前值 | 用途 |
|---|---|---|
| `missing` | 20（%） | 缺失率告警阈值：超过即提示修复 |
| `nsample` | 30 | 最小样本量：低于即在统计功效上给低置信提示 |
| `qpos` | 5 | 队列告警位次：排到该位次以后即提示等待 |

**不要**把这三个值当定稿。

> **v47 变更**：顶栏那颗常驻的「阈值待确认」徽标已撤，界面上不再挂这个标注。
> 理由：它标的是一句**局部**待办（参数配置页「阈值依据」卡上写着同一件事），
> 挂在全局顶栏上等于把局部待办说成全站常态，且会跟着用户走到任何页面 ——
> 对不关心统计口径的人只是一句噪声。
> 阈值本身一个没撤：仍按上表生效、仍收在 `THRESHOLDS` 里，
> 「待确认」这件事改由本节与常量注释承载。

## 2.5 样本档案：数据口径与列表

### 队列口径必须与「样本对齐」页同源

样本档案的 75 例不是随手造的，它**必须**等于「样本对齐」页写死的队列规模：

| 项 | 值 | 含义 |
|---|---|---|
| 队列 | 75 | 总样本数 |
| 基因组覆盖 | 75 | 全部样本都产出了 |
| 转录组覆盖 | 75 | 全部样本都产出了 |
| 蛋白组覆盖 | 71 | **恰好 4 例缺失** |
| 三组学共同样本 | 71 | 交集 |

也就是 `MISS_PROT = [S004, S021, S052, S063]` 这 4 例。**这 4 例同时是质控结论「不合格」的 4 例** ——
缺失原因（血浆溶血 / 血清量不足）与质控结论是同一件事的两种说法，改一处必须回头核另一处。
验证脚本会从样本数据现算这组覆盖数，再与页面上写死的值对照，漂移会立刻失败。

数据层是「4 例手写（带故事：齐全 / ID 映射 / 血浆溶血 / 血清不足）+ 71 例按模板生成」。
生成用固定数组决定分布、伪随机只决定具体数值 —— 真随机会让每次刷新的顺序都变，断言无从下手。

### 列表的列语义

样本列表一列一个维度，开发时注意三列的特殊约定：

- **质控结论**列显示短结论（合格 / 部分合格 / 不合格），完整结论（如「组织合格 · 血浆不合格」）
  放在 `title` 里。窄表放不下长文本。
- **组学覆盖**列是三个字标（基 / 转 / 蛋），已产出为浅青实底、未产出为灰描边。
  这一列回答的是「缺哪一路」，**不要**改成进度条或百分比。
- **资料**列是已归档文件的数量，点进详情看清单。

交互上：**样本搜索框与四维筛选同处列表卡顶部**（v16 把原独立的「查询」卡并入列表；
搜索关键词与筛选共用同一份状态，搜了列表就跟着变），点击列头排序、每页 15 条分页、
**选中一行，下方即出现该样本的指标 / 信息 / 血缘 / 跨组学 / 资料**。
**选中项永远可见** —— 切到第 37 位的样本时列表会自动翻到它所在的那一页，
否则列表上没有任何标记，用户会以为没选中。

### 样本信息的字段来源

信息卡的 27 个字段是**四路现算**合成的，不要照着界面抄成一张静态表：
顶层字段（受试者 / 采集物 / 采集时间 / 存放条件）+ 血缘谱系派生（分装数 / 衍生数 / 原始登记 ID）
+ 跨组学派生（所属项目）+ `meta`（临床 / 存储 / 质控 / 知情同意）。
存一份成品字段表等于埋一个没人看得见的过期缓存。

状态值一律「浅底 + 同系深字」，且**结论文案与状态色绑成一对**（`QC_LEVELS` / `CONSENT_STS` 的选项
自带状态色）—— 表单里没有第二个状态源，就没有改岔的余地。

## 3. 告警的触发方式：状态驱动，不是开关

原型里**没有**「演示某个异常」的按钮。看到什么提示，取决于当前上下文：

| 告警 | 由什么状态决定 | 真实操作路径 |
|---|---|---|
| 格式不支持 | 上传文件扩展名不在白名单 | 拖拽区真选一个 `.xlsx` |
| 缺失率过高 | `CTX.miss > THRESHOLDS.missing` | 载入「含缺失矩阵」示例后进样本对齐页 |
| 样本量不足 | `CTX.n < THRESHOLDS.nsample` | 样本对齐页把「分析范围」改成 22 例的子集 |
| 算力排队 | 提交时队列里还有任务 | 任务运行页点「开始运行」即入队 |

状态集中在 `src/app.js` 的 `CTX`（缺失率 / 样本数 / 排队位次 / 集群负载），
`syncAnoms()` 在每次进入页面时按它重算该显示哪条告警。
新增告警请照这个模式加，不要再加专门的触发按钮。

## 4. 原型边界：哪些是前端模拟

界面上看不到这些说明，但开发时需要知道。接口契约见 PRD 第 6 章（7 个端点）。

| 位置 | 现状 | 正式实现 |
|---|---|---|
| 数据上传 | 读浏览器文件对象，取文件名与大小 | 对象存储，库里只留引用 |
| 知识库解析 | 要点为前端生成 | 向量化后的原文片段、页码定位与出处链接 |
| 检索 | 命中结果在前端 | 向量检索 + 重排服务 |
| 图谱 | 圈图占位 | Cytoscape 网络图模块 |
| 项目分享链接 | 前端生成，不指向真实服务 | 二维码 + 访问审计 |
| 工具运行 | 定时器推进进度 | 真实调度与 job 状态回传 |

**不是模拟的部分**（已按真实行为实现，可直接照做）：
真实文件选择、真实下载、扩展名校验、拖拽落文件、告警的状态驱动、跨页返回栈。

## 6. 仍需遵守的既有约束

- **配色**：青色 `#106376` / 深 `#0A4655` / 浅底 `#E3F0F3` / 描边 `#A6C9D2`；
  两套 token 必须同时改（CSS `--color-brand*` 与 `app.js` 的 `C.*`）。
- **左栏是深色的，顶栏左段与它拼成 L 形外壳**（v18，见第 10 节）。块内前景色一律走
  `--color-rail-*` 三档浅字；深底上沿用页面浅底配色的值（`--color-ink` / `--color-brand`）等于隐形，
  改这块必须跑「块内每个可见文字的实际前景 vs 实际背景 ≥ 4.5」的断言 —— 光看 token 名看不出来。
  左栏宽度只有一个来源 `--rail-w`：网格列宽与顶栏深色块都读它，三档断点也只改它。
- **无障碍**：每张图都要有「查看数据表」替代视图（v19 起无例外 —— 对齐矩阵此前漏配，已补齐）。
  图注与坐标轴标注保留；v17 撤掉的是「这张图说明了什么」解释段，不是图注。对比度按 WCAG 2.1 AA。
- **图表的显示尺寸由图自身的自然尺寸决定，不由容器决定。** 小 viewBox 的图铺满宽卡片会被等比放大，
  字号跟着失真（对齐矩阵曾从 19px 放大到 35px）。用 `wrap()` 的 `maxW` 参数锁住自然尺寸，详见第 11 节。
- **涨红跌绿**（中国习惯），金额用 ¥。
- **表格的列对齐只有一个出口：`.tbl th` 与 `.tbl td` 同一套居中**（v20）。
  表头与单元格内容都居中，数字与日期列也不例外；不要在单元格上挂对齐工具类把它改回单边 ——
  以前是「表头左对齐 + `.num` 右对齐」，参数确认摘要的「取值」列整列右飘就是这么来的。
  单元格里用 flex 排版的内容要显式 `justify-content: center`（`text-align` 对 flex 容器无效）。
- **必填字段统一用提醒色星号 `*` 标识**（v20）：字段名后挂 `.req`，表单尾部一行 `.frmlegend` 图例，
  控件再加 `aria-required="true"`。以前样本登记与新建项目挂灰色「必填」小标签、工具参数用红色 `*`，
  同一站两种说法。星号用 `--color-warn` 而不是正红：红色留给「错误 / 不合格」。
  标了必填就要真的拦得住（工具抽屉已加提交前校验）。
- **返回只有面包屑这一条路。** 各页顶部的「← 返回上一步」返回条 v17 已撤；顶部面包屑的每一段都可点，
  上一级与横向菜单都能从这里回去。不要为了「方便」把返回条加回来。
- **界面上不放解释性说明条。** 需要解释的内容写进本文件，不要加回 `.note` / `.pubnote`；
  验证脚本会断言 `.note` 数量为 0。
- 三个组学口径（基因组 / 转录组 / 蛋白组）、队列 75 例、共同样本 71 例是核对过的数字，不要随手改。

## 7. 已从界面撤下的辅助内容（保留备查 · v16）

工作台右栏原来的「辅助功能」卡（术语表 / 无障碍说明 / 本期范围与排除项）已从界面移除，
三个弹窗一并撤下。内容原样留在这里，开发需要时从这里取。

### 7.1 术语表

| 术语 | 中文解释 |
|---|---|
| padj | 校正后的显著性水平。样本越多假阳性越多，所以要校正；越小越可信，0.05 是惯例分界。 |
| log2FC | 表达变化倍数取以 2 为底的对数。1.0 表示表达量变化到原来的 2 倍或一半。 |
| ACMG | 美国医学遗传学与基因组学学会制定的变异致病性分级标准，分致病、可能致病、意义未明、可能良性、良性五档。 |
| FPKM / TPM | 基因表达量的标准化单位，用来消除测序深度和基因长度带来的偏差。 |
| 曼哈顿图 | 把全基因组的关联显著性按染色体位置排布出来的图，高耸的点像曼哈顿的天际线。 |
| VIP | 代谢组中衡量某个代谢物对组间区分贡献大小的指标，通常以 1 作为筛选分界。 |
| 队列位置 | 任务在算力队列中的排位。数字越小越先执行，位置 1 表示下一个就轮到。 |

### 7.2 无障碍说明（WCAG 2.1 AA）

- **不靠颜色传达状态。** 四类异常提示同时带有图标与文字标签（阻断 / 警告 / 提示），色觉障碍用户也能区分。
- **图表都有数据表替代视图。** 每张图下方提供「查看数据表」，屏幕阅读器与色觉障碍用户可读取原始数值。
- **正文对比度 ≥ 4.5:1，正文最小 14px。** 次要说明文字不小于 11.5px 且对比度 ≥ 4.5:1。
- **全流程键盘可达。** 焦点顺序与视觉顺序一致，聚焦状态有 2px 可见描边。
- **尊重减少动态效果偏好。** 开启系统「减少动态效果」后，所有过渡动画自动关闭。

### 7.3 本期范围与排除项

- **首版原型包含（P0）**：工作台、数据汇集、样本对齐、流程模板、参数配置、任务运行、结果全景，共 7 页。功能编号 F-01 – F-09、F-14。
- **本期扩展（P2）**：医学知识库、自有知识库、知识图谱，共 3 页。功能编号 F-16 – F-18。
- **本期不做**：模型解释（SHAP 全局重要性、单样本解释、LIME 局部解释对比）与低代码建模工作台。两者都属于机器学习模型侧评估口径，与本次组学分析主线不同源，本期从原型中移除。
- **明确排除**：真实模型训练与算力调度（全部前端模拟）；用户体系与权限管理（仅以角色切换器表达差异）；多语言；移动端专门适配（仅做响应式布局）。

## 8. 下载：确认弹窗与真实产出（v17）

界面上 14 条下载 / 导出入口走同一条链路：**点击 → 确认弹窗 → 确认后由浏览器真实落地文件**。
确认框里写清四件事：文件名、格式与行数、体积、来源（在哪一页、从哪张表算出来的），外加一句说明。
开发接后端时只需替换 `DL` 注册表里每个条目的 `build()` 返回值，确认框与按钮不用动。

> **v46**：`DL` 注册项 15 → 14（「基因档案」的 `DL.genes` 随页面整块撤除），
> 同时**补回一条本该存在却一直缺的** `DL.alignmatrix`（任务运行页 › 对齐明细）—— 详见 §38.8。
> 判定那条「入口齐备」的断言也从「数个数」改成「按名字比集合」，见 §38.8。

## 10. 深色左栏与 L 形外壳（v18）

左栏底色改用品牌深色，顶栏左侧与它**等宽**的一段同色，两块拼成完整的「L 形」外壳。

**为什么顶栏左段也要跟着深**：只改左栏的话，品牌区会在深色柱子上压一个白块，左上角出现一个生硬的直角；
而且 logo 正落在深色左栏的上方，白色顶栏会把「外壳」这一层切碎。面包屑、角色切换器、阈值标签仍在
白色区，前景色不用动。

| 部位 | 底色 | 前景 |
|---|---|---|
| 左栏 / 顶栏左段 | `--color-brand-deep` `#0A4655` | — |
| 一级（分组标题、工作台） | 同上 | `--color-rail-ink` `#EEF5F7`（9.4:1） |
| 二级子项 | 同上 | `--color-rail-ink2` `#BFD8DE`（7.0:1） |
| 计数 / 页脚 | 同上 | `--color-rail-ink3` `#9DBFC7`（5.3:1） |
| 分组图标 | 同上 | `--color-rail-accent` `#7FD0E2`（5.9:1） |
| 顶部 logo 方块 | `--color-brand-soft` `#E3F0F3` | `--color-brand-deep`（8.9:1） |
| 当前项 | `--color-brand-soft` `#E3F0F3` | `--color-brand-deep`（8.9:1） |
| hover | `rgba(255,255,255,.10)` | 提到 `--color-rail-ink` |
| 焦点环 | — | `--color-rail-accent`（默认的深青在深底上是 1:1，等于没有） |

当前项在深底上仍然沿用「浅青块 + 深青字」的整块高亮 —— 深色导航里，一眼能扫到的底色才扛得住
「我在哪」这个问题，13px 字号下的描边或竖线太轻。hover 用半透明白块，与选中态的浅青块不会混淆。

**三件不能省的事**：

1. **左栏宽度只有一个来源。** `--rail-w` 同时供网格列宽与顶栏深色块的宽度，三档断点（1400 / 1180 / 900）
   也只改这一个值，`.shell` 不再自己写列宽。两边各留一份数值，改一处忘一处就会出现「深色块比左栏宽 2px」
   这种只能靠眼睛找的问题。
2. **左栏收起时顶栏深色块必须一起收。** 不收的话白底上会剩一根没有柱身的色块，而它的文字是浅色 ——
   「收起左栏」这个动作会顺手把品牌区变成不可读。状态类同时挂在 `.shell` 与 `.app` 上（`setRail()`），
   用 `.app.is-railoff` 选择，没有走 `:has()`。
3. **深色块是伪元素，不是 DOM 节点。** 顶栏用的是 `::before`（`bottom: -1px` 顺带盖掉顶栏那条 hair 分界线，
   否则深色柱会被一条浅灰线拦腰截断）。伪元素不是节点，意味着任何「沿 DOM 往上找背景色」的逻辑都摸不到它。

**验证怎么钉住它**：不查「用了哪个 token」，而是逐个可见文字元素算**实际前景 vs 实际背景**的对比度，
全部 ≥ 4.5。深底压深字在 DOM 数据上完全正常（元素在、文字在、`aria-current` 也对），只有算对比度才暴露。
顶栏品牌区压在 `::before` 上，那里必须显式取 `::before` 的计算色当背景 —— 否则会量出 1.1:1 的假结论。
结构上再钉两条：深色块宽度 == 左栏宽度、品牌区右边框正压在深色块右缘。

## 11. 图表的显示尺寸：小 viewBox 的图不许被容器拉伸（v19）

**问题**：样本对齐页的 3×3 对齐矩阵在宽屏上大得不成比例 —— 格子占满整张卡片，
里面的数字看着是正文的两倍多，整张图把同页的「未匹配样本」表顶到了首屏之外。

**成因不是设计值大，而是 SVG 的缩放方式**。所有 `.chartbox` 里的图都是 `width:100%`，
即「按容器宽度等比放大」，放大倍率 = 容器宽 ÷ viewBox 宽：

| 图 | viewBox 宽 | 卡片内容宽（1440 视口） | 放大倍率 |
|---|---:|---:|---:|
| 曼哈顿图等 13 张 | 640 | 772 | 1.21× （字号 11 → 13.2，在设计内） |
| **对齐矩阵** | **416** | **772** | **1.86× （数字 19 → 35，图高 666px）** |

viewBox 越小，被拉得越狠。矩阵图是**全站唯一 viewBox < 500 的图**，所以只有它出问题。

**做法**：给 `wrap()` 加第 5 个参数 `maxW`，图可以声明自己的**自然显示宽度上限**，
不传则维持原来的铺满行为。对齐矩阵传 `maxW = viewBox 宽`，即「绝不放大」，
多余宽度由 `margin: 0 auto` 居中 —— 这样在任何屏宽下字号都恒定，不会「屏越宽字越大」。

| 部位 | 值 | 说明 |
|---|---|---|
| 格子 | 104 单位（格内净宽 98） | 格间距 6 对称铺开 |
| 矩阵数值 | 19px | 与指标卡数值 22px 同量级、略低一档 |
| 轴标签（基因组 / 转录组 / 蛋白组） | 12px | 与表格字号 12.5px 对齐 |
| 格内副标签（交集 / 自身样本数） | 10px | 与页面其它辅助小字一致 |
| 整体 | 416 × 366 | 居中于 772px 卡片内容区 |

效果：卡片高度从 756px 降到 492px，「未匹配样本」表回到首屏。

**顺带修掉的一处不一致**：矩阵图原先是一个**特例** —— 它绕过 `renderChart` 直接
`host.innerHTML = wrap(...)`，因此既没有尺寸上限，也**没有其它 13 张图都有的「查看数据表」替代视图**
（3×3 的 75/71 对读屏用户完全不可得，`aria-label` 只写了图名）。本轮把它注册进 `CHARTS.align`，
尺寸约束与无障碍替代走同一条通路，特例消失。

**验证怎么钉住它**：量的是**屏幕实际字号**，不是 viewBox 里的值，也不是容器宽度 ——
SVG `text` 的 computed `font-size` 返回的是 viewBox 单位，必须乘缩放比（实测宽 ÷ viewBox 宽）
才是用户看到的字号。判据四条：缩放比 ≤ 1.05、数值字号落在 14–24px、最小字号 ≥ 9px、
9 格数值齐全且替代视图里的数与之同源。

## 12. 列表对齐、样本筛合并、任务流水线、必填标识（v20）

四条改动，都是「同一件事在站内有两套说法」的收敛。

### 12.1 全站表格：表头与内容同一套居中对齐

**问题**：此前表头居中、单元格左对齐，长表在宽屏上读起来像两栏错位；不同页各写各的 `text-align`。

**做法**：`.tbl th` 与 `.tbl td`（含 `.num` 数字列）统一 `text-align: center`。数字列原先靠右是为了对齐小数点，
但本项目表格普遍列数多、单列窄，居中反而更容易看出同列差异。`.dname`（数据集名）等长文本列同步适配居中。

**验证怎么钉住它**：两条一起断，缺一不可。
① 静态：遍历**文档里全部** `table.tbl`（含 `display:none` 的页与未打开的弹窗）的计算值，`bad` 必须为空；
② 几何：切到 gene / p05 / p07 三页，用 `Range` 取表头与每个单元格内容的**实际水平中心**，差值 ≤ 2px。
只断静态值会漏掉「表头左、单元格右」这类只在像素上看得出的错位；只断几何则会漏掉当前没渲染的页。
几何探针同时记录 `seen`（量到了哪几张表、各几列），数字对不上时先看是哪张表没渲染出来，而不是去调阈值。

### 12.2 样本档案：样本 ID 搜索并入筛选行

样本 ID 是「定位到某一例」的入口，和疾病 / 质控 / 组学 / 状态四个下拉是同一件事（缩小候选集），
此前却单独占一行 `filtbar`，视觉上像两个互不相干的工具。现在关键词框与四个下拉同排，
候选 chips 与空态移到筛选栏之后 —— 顺序就是「先筛、再看命中」。

### 12.3 任务运行页：纵向阶段列表 → 横向流水线

纵向列表看不出「跑到第几步了」。改成一条横向流水线：节点按 `RUN_STAGES` 依次排列、节点间有箭头连线，
节点状态由 `data-pipe-state`（`wait` / `run` / `done`）驱动，已完成的连线点亮。
`RUN_STAGES` 是流水线的**唯一来源**（含各阶段计划耗时），节点名、工具版本、耗时文案都由它渲染。

状态全部从运行记录反查，不硬编码：真跑一次能看到 `wait → run → done` 的推进（运行中节点带本阶段百分比与剩余时间），
取消后不留「运行中」的节点、已完成的阶段保留。跑完五个节点全绿、四条连线全亮。

### 12.4 必填字段：统一提醒色星号 + 表单图例

原先三处表单各用各的写法（有的挂灰色「必填」标签，有的什么都不标）。统一为一套：
字段标签上的 `.req` 星号取 `--color-warn`（提醒色），表单底部一行 `.frmlegend` 说明「* 为必填项」，
同时给控件挂 `aria-required="true"` —— 只靠颜色表达必填对读屏用户等于没说。

工具抽屉的三个必填项（R1 / R2 / 参考基因组索引前缀）**真的拦得住空值**：清空后点「运行此工具」会被拦下、
给出提示并把焦点回落到该字段；填回去就能提交。拦的是空值，不是按钮本身。

**验证怎么钉住它**：数星号时**不能**用 `.req` 一把捞 —— 字段标签上的星号（`.fld__l .req`）和
图例自己那颗（`.frmlegend .req`）是两种东西，一把捞会把「1 个必填项」量成 2。断言写成

### 13.3 画布升级为编辑器形态

| 部位 | 做法 |

| 连线 | 带箭头（`marker-end`），折行时绕 U 型而不是斜穿 |
| 卡头 | 流程名 + `N 节点 / N 连线` + 状态徽章；右侧「重置 / 全屏 / 节点列表」 |
| 缩略图 | 右下角，网格第二列（**不是绝对定位**）—— 绝对定位迟早与第二行右端的节点重叠 |
| 底部 | 状态差（模板 N 步 → 当前 M 步）+ 「保存为自定义流程」+「运行此流程」 |

「用这个流程」从卡头搬到卡头下方的操作栏并改名**运行此流程**：底部是这条流程的收口动作，
卡头再留一个同义按钮就是两个入口做同一件事。

**两个必须踩过才知道的坑**：

1. **`FAI[name].p` 存的已经是完整的 `<path …>` 标记**（build.js 直接存 innerHTML），不是 `d` 属性值。
   照 `ico()` 的形式再包一层 `<path d="…">` 会把属性截断，余下的 `"/>` 会当成**文字漏到画布上**
   （节点名前面多一坨 `"/>`），且 DOM 数得出来的节点数完全正常。
2. **嵌进外层 SVG 的 `<svg>` 必须自带 `x/y/width/height`**，否则新视口尺寸为 0，图标以 0×0 渲染 ——
   数得到 7 个 `<svg>`，屏幕上什么都没有。判据必须是 `getBoundingClientRect()` 的实际像素。

**尺寸约束**：右侧缩略图占去一列约 150px，所以节点卡的宽 / 间距不能按「越宽越好」调 ——
viewBox 越宽、等比缩放的倍率越小，屏幕上的字反而越小（同 §11）。实测 viewBox 852×168 落在 694px 的画布里，
缩放 0.815，节点名 11.5 → 9.4px，与 v20 之前的 9.3px 持平（没有为了加缩略图而牺牲可读性）。
名字截断到 8 字 + 省略号，**全名在 `aria-label` 与「节点列表」表里都在**，截断不等于丢信息。

### 13.4 工具库点工具 = 往画布末尾接节点

点工具库里的任意工具：往画布末尾追加一个节点、补一条「上一节点 → 新节点」的连线（不留孤岛），
**同时打开该工具的参数配置抽屉** —— 新节点默认就是要配参数的，分两步点反而多一次点击。
画布是**草稿**，模板只负责给初值：

- `CANVAS = { base, nodes, links }` 是画布的唯一事实来源；
- 点左侧列表换流程 = 换模板，会丢弃草稿（选模板就该看到模板原样）；
- 卡头「重置」把自编排的节点全撤掉；
- 底部「保存为自定义流程」把草稿固化进流程列表（此后可再选中、再改动），接后端时这里换成 POST 即可。

**验证怎么钉住它**：先显式选一条短流程当基线（f11，5 节点 4 连线），再点工具，断言
`steps == 基线 + 1`、`links == 基线 + 1`、且恒等式 `links == steps - 1` 成立 ——
只断「节点多了 1 个」会漏掉「节点加了但没连线」这种孤岛。
另有一条：图上的名字是截断的，但「节点列表」最后一行必须是**全名**。

### 13.5 截图状态：浮层不会自己消失

`goto()` 负责收起全屏编排区，但**不关浮层**。`31-proj-share.png` 是故意把分享弹窗留在画面里的，

**通则**：凡「故意留下浮层」的截图，其后第一张「要干净画面」的截图必须自己收尾，不能指望导航顺手清掉。

另外画布是可编辑的，所以「流程模板 + 画布」这张定妆照拍之前先 `__orchForget()`（撤掉探针存下的草稿流程）

## 15. 样本血缘谱系：改为横向「层级 = 列」泳道图（v23）

**需求**：血缘谱系按参照截图的样式与配色呈现 —— 四列泳道（队列个体 → 样本源 → 分装样本 → 衍生模型）、
浅蓝列头带、彩色顶栏节点卡、正交折线连线。

### 15.1 布局：从「纵向四层居中」到「横向列式」

| 部位 | 旧（纵向） | 新（横向，对齐参照图） |
|---|---|---|
| 走向 | 自上而下四层，每层居中 | **层级 = 列**，从左往右；列头带铺满整行 |
| 列头 | 无 | `队列个体 / 样本源 / 分装样本 / 衍生模型`，**由数据现算**（`LIN_COLNAME` 按节点 `k` 定） |
| 节点卡 | 白底描边 + 左侧色条 | **彩色顶栏卡**：上半是实色顶栏 + 白色 ID（mono），下半浅底副标；队列个体卡整卡浅蓝 + 图标 + 蓝色标题 |
| 连线 | 三次贝塞尔曲线 | **正交折线**（水平 → 竖直 → 水平），同一父节点的多条边共用折点，竖直段自然并成干线，不做交叉斜线 |
| 徽标 | 右上角实色圆（0 路灰色） | 右上角**白底圆**，0 也照画 ——「已分装但未送测」是有信息量的状态（参照图同样如此） |

**列数是数据驱动的，不是写死 4 列**：S068 的原始登记 ID 有别名，血缘多一层 → 渲染成 5 列
（列头多一个「原始登记 ID」）；生成样本只有受试者 → 采集物两层，就是 2 列。布局函数只认 `n.lv`。

### 15.2 配色：一套自带的三组学色 + 深度校准

参照图的配色和站内 token 不同源（它是「蓝 / 青 / 紫」三组），做成独立常量 `LINC` +
`LIN_SKIN`（每个层级一份 `top` 顶栏实色 / `body` 卡底）：

- 蓝 `#1F6FD6`（样本源）· 青 `#14808F`（分装样本）· 紫 `#7C3FD0`（衍生模型）——
  三个顶栏白字实测 **4.88 / 4.65 / 6.04**，全部 ≥ 4.5；
- 「队列个体」卡没有顶栏，整卡浅蓝底 `#EAF2FC` + 蓝色标题：参照图的蓝 `#1F6FD6`
  铺在这底上只有 **4.32**，差一口气 —— 标题 / 图标 / 选中描边用加深一档的 `#1A63C4`（**5.13**）；
- 列头深灰蓝 `#4A6D93` 对浅蓝头带 **4.76**，副标灰 `#63748A` 对白底 **4.78**；
- **为什么不全用 token**：这三种色承担的是「一眼分列」的类别编码，品牌青只有一档、
  拉不开三个层级；但对比度必须按同一把尺子量，不达标就加深，而不是换 token 交差。

**边标签**（分装 / 消化培养 / 基质胶培养 / 皮下移植）落在**最后一段水平线**的上方：
同 y 时是整条线中点，分叉时是「折点 → 子卡」段 —— 白描边压线，不与连线糊在一起。

### 15.3 尺寸：锁自然宽度，三列图不许被容器放大

生成样本的基础血缘只有 3 列（自然宽 750），容器却有 1110 —— 不锁 `maxW` 就会被放大 1.48 倍，
字与卡片都比四列样本大一圈，同一个控件切换样本时长相不一。**v19 对齐矩阵的同一个坑**。
锁住后两种列数都 1:1 居中，节点 ID 12.5px 实显就是 12.5px。

**画成按钮的必须真的接得住点击**：节点仍是 `role="button"` + Enter / Space（点节点筛组学的交互保留）；
顶栏若画成 path，白字对比度探针（只认 rect / circle 的 fill）就找不到背景 —— 顶栏用两个 rect 拼
（圆角 rect + 方形补丁压平底边两角）。

### 15.4 验证怎么钉住（297 → 305，全绿）

- **列头 = 数据现算**：S037 四列名全等 + S068 多一层「原始登记 ID」（切换探针现量）——
  只断 S037 等于把写死的 4 列也放过了；
- **同层同列、列宽等分**：列 x 坐标等差（步长 = viewBox 宽 ÷ 列数），不写死具体 x；
- **正交折线**：`path[marker-end]` 的 `d` 里**含 C 命令即失败** —— 退回贝塞尔就露馅；
- **不被拉伸**：`scale == 1` 且容器宽 > viewBox 宽；
- **顶栏白字对比度 ≥ 4.5**：全站统一探针跑在图渲染之前（#linBox 还是空的），够不着这里，必须单独量；
- **图标真的渲染了**：内嵌 `<svg>` 要有 `x/y/width/height`（v21 的教训），判据取 `getBoundingClientRect()`；
- **节点列表替代视图**：行数 == 节点数。

**一个旧断言的教训**：「默认展开 boxH > 300」是纵向四层（约 500px）时代的写死值，横向 3 行是 284。
图的高度现在是「列数 / 每列行数」的函数（3 行 284、1 行 132），阈值绑到 viewBox 高度上才不会再碎。

## 16. 样本血缘谱系：横向泳道 ⇄ 上下结构双视图（v24）

**需求**：给血缘谱系加一个切换按钮，点击变成上下结构的血缘谱系。

### 16.1 一个模块、两个方向、同一份数据

按钮放在卡片头「节点列表」旁边，文案写的是**点下去会变成什么**（横向态显示「上下结构」，纵向态显示「横向泳道」）——
写成当前状态会让人以为它是个只读标签。`LIN_AXIS = 'col' | 'row'`，默认横向。

| | 横向泳道（col，默认） | 上下结构（row） |
|---|---|---|
| 层级落在 | 列（浅蓝列头带） | 行 |
| 节点卡 | 176 × 54 | **250 × 90**（与参照图同尺度） |
| S037 实测 | viewBox 1000 × 284 | viewBox 1099 × 692 |
| 分叉点 | 不画 | 父节点脚下画小圆（≥2 个子节点才画） |
| 边标签 | 最后一段水平线上方 | 两行之间的空白带 |

两套布局**共用同一个 `linCardSVG()`**（节点卡的画法是数据 + `LIN_GEO[方向]` 的几何参数，不是两段复制代码）——
否则「改一处忘了另一处」只是时间问题。

**方向是 UI 偏好，不是样本属性**：切样本、切 tab、折叠展开都不复位。都复位的话，用户点了「上下结构」，
换个样本又弹回横向，得反复点。

### 16.2 顺带补上一条缺失的真实关系

参照图里「受试者 → 样本源」是有连线的，但数据里一直缺 `from` —— 受试者成了**孤立叶子**，
在横向视图里看着像一张没头没尾的孤卡。补上后每个样本的边数 +1（S037 5 → 6）。
**连带改了 4 条旧断言**：它们把边数写死成 5 / 3 / 0。现在一律写**结构不变式**：

```
edges == nodes - 1        # 每个非根节点恰有一个父 → 树连通
```

写死数字的断言在下一次补一条边时必然全红，而且红得毫无信息量。

### 16.3 「锁自然宽度」要落到布局阶段，不是等画完再缩放

v19 / v23 两轮都在同一条上栽过：图宽超过容器就被 SVG 等比缩放，字号、卡片、图标一起变，
同一个控件换个样本长相就不一样。本轮两个方向都改成**布局阶段自己压进 `LIN_MAXW = 1100`**：

- 上下结构：槽距 `S` 由**叶子数**反推 —— `S = min(NW + GAP, (LIN_MAXW - NW) / (叶子数 - 1))`。
  S037 有 4 个叶子（血浆分装 + 三个衍生模型），按固定 326 排就是 1228 宽被压到 0.904 倍；收窄到 283 后正好 1099。
- 横向泳道：列宽 `CW = min(250, LIN_MAXW / 层数)`，`math.floor` 取整（避免 `408.333…` 这种路径坐标）。

修完两个方向、两个样本（S037 四层 / S068 五层）实测 `scale` 全是 **1.000**。

### 16.4 验证怎么钉住（305 → 312，全绿）

| 断言 | 判据 |
|---|---|
| 默认横向 + 按钮文案 | `axis == 'col'`、按钮标签 `上下结构`、图标真的渲染、**命中测试**通过 |
| 点一下切成上下结构 | `axis == 'row'`、y 方向有 4 个层级、卡宽 250、出现分叉点 |
| **换方向不换数据** | 节点 / 边 / 徽标 / 节点列表行数四处与横向视图逐一对齐 |
| 上下结构也正交、也不被缩放 | `curved == 0`、`scale == 1`、`vb宽 <= 1100 <= 容器宽` |
| 对比度与图标 | 顶栏白字 `>= 4.5`、内嵌图标 `getBoundingClientRect` 有实际像素 |
| 方向跨样本 / 跨 tab 保持 | 切到 S004、切到 gene tab 再回来，`axis` 仍是 `row` |
| 再点一下切回横向 | `axis == 'col'`、层级回到 x 方向、分叉点撤掉 |

「命中测试」不是形式：`elementFromPoint` 取按钮中心点，必须能被自己接住 ——
画成按钮却点不动是本项目反复出现的假交互。**注意测试前要 `scrollIntoView`**：
血缘卡在页面中段，不滚进视口时 `elementFromPoint` 返回 `null`，那不是按钮坏了，是它不在屏幕上
（第一版探针就报了这个假警报）。

## 17. 特定样本条：条底上色、四格按血缘四层配色（v25）

### 17.3 「有底色」不等于「看得见」

第一版条底取的是 `#F1F7FD` —— 色值上是彩的，可它与页面底 `--color-paper: #F5F8FC`
只差 **1.4% 亮度**，屏幕上仍是一条白带。改到 `#E0ECFA` 后与页面底的亮度比是 **1.12**。
所以断言不看色值，看**与页面底的亮度比 ≥ 1.10**。

层次是**彩带深、四格浅**（条底亮度 0.8274，四格底 0.851 ~ 0.883）：彩带铺底，四格像四张
浅色卡浮在它上面。反过来做会让同色相的那格（样本 ID 的蓝）整个陷进条里，只剩色条和字看得见。
四格底与条底的亮度差实测 0.023 ~ 0.056。

⚠️ 这个层次**不能用对称比来判方向**：`ratio()` 算的是 `(max+.05)/(min+.05)`，恒 ≥ 1，
写成 `> 1.0` 等于永远通过 —— 真把四格做得比条还深，那条断言照样是绿的。所以判的是
**亮度本身**且要求拉开 ≥ 0.02，光「不等于」不够。

## 18. 样本详情：五块内容从页面搬进右侧滑出抽屉（v26）

### 18.1 刻意不带遮罩，让列表继续可点

| 决策 | 取值 | 理由 |
|---|---|---|
| 遮罩 | **不加** | 档案的用法是「边翻边看」。加了遮罩就得「关掉 → 再点」，换一例多一步 |
| 让位方式 | `.content { padding-right: calc(var(--samp-drawer-w) + 20px) }` | 抽屉**压在**列表上会让右侧几列点不到；内缩才是「列表真的让出了宽度」 |
| 宽度 | `--samp-drawer-w: 840px`（唯一来源，≥1400 视口下内容区 770） | 血缘图 + 跨组学 7 列表都得住得下 |
| 点另一行 | 内容**原地换**，不关抽屉、不重播滑入 | 关掉重开会闪一下，像「换了个页面」 |
| 收起时机 | Esc / 关闭按钮 / 切 tab / 跳页 | 它是某一页的浮层，留在屏幕上就是幽灵面板 |

`hidden` 管「在不在」，`.is-open` 管「滑没滑到位」—— 关闭是**先摘类播 0.26s 动画、
300ms 后才 `hidden`**，直接置 `hidden` 会让抽屉「啪」地消失。

### 18.2 顺带修掉一个真 bug：幽灵抽屉

`openSampDrawer()` 原先写着「`!hidden` 就直接 return」。
于是走这条路径时会留下第三个姿态 —— **`hidden === false`、`is-open` 已被摘掉**：

> 关抽屉（`is-open` 摘了，300ms 后才 `hidden`）→ 在这 300ms 内又点开 →
> `clearTimeout` 撤掉了收尾，`!hidden` 又让函数提前返回 → `is-open` 再也加不回来。

表现是抽屉**永远停在屏幕外**，而 `getBoundingClientRect().height` 是正常值（不是 0）、
`hidden === false`、DOM 里数据样样齐全 —— 只有 `elementFromPoint` 返回 `null`。
真实触发路径：切到基因 tab 再切回来、其间点到列表行。
修法是把「开着」定义成两个条件同时成立，并且**只在真的已是打开态时才提前返回**：

```js
function sampDrawerOpen() { var d = $('#drawerSamp');
  return !!d && !d.hidden && d.classList.contains('is-open'); }
function openSampDrawer() {
  var d = $('#drawerSamp'); if (!d) return;
  clearTimeout(SAMP_DRW_T);
  var was = !d.hidden;
  if (was && d.classList.contains('is-open')) return;
  d.hidden = false; document.body.classList.add('is-sampdrawer');
  if (!was) renderLineage();            /* 容器宽 0 → 真实宽，必须重排一次 */
  requestAnimationFrame(function () { requestAnimationFrame(function () {
    d.classList.remove('is-open'); d.classList.add('is-open'); }); });
}
```

### 18.3 血缘图的宽度：从「写死 1110」改成「按容器实测」

血缘图原先用常量 `LIN_MAXW = 1100`（画布实测宽）。搬进抽屉后容器变成 770，
写死会让 770 宽的图被算成 1100 → 整体被压缩 0.7 倍。改成：

```js
function linMaxW() {                    /* 抽屉收起时 #linBox 宽为 0，回退到抽屉内容宽 */
  var box = $('#linBox'), w = box && box.clientWidth ? box.clientWidth : 804;
  return Math.max(560, Math.min(1100, w));
}
```

### 18.4 卡宽与槽距要**联合求解**，不能先定槽距再缩卡

上一轮纵向布局的写法是「先算槽距 S，S 不够大再把卡缩到最小系数 0.7」。
搬进抽屉后 S 被压到 173，卡缩到 175 —— **卡比槽距还宽 2px**，
三张衍生模型叠在一起。而这一眼看不出是「重叠」，只觉得「卡挨着卡」。

正解是把 `卡宽 NW = 槽距 S − 留白 LINGAP` 代进跨度约束里解 S：

```
span = NW + (slots−1)·S ≤ maxW   ⇒   S ≤ (maxW + LINGAP) / slots
```

横向「层级 = 列」同理：列宽 CW 收窄后，卡按 `(CW − LINGAP) / NW0` 缩，
而不是给系数拍一个最小值。两种排布共用同一个 `linFit(可用宽, 自然宽)`：

| 样本 | 方向 | 卡宽 | 同层留白 | 图宽 / 容器 | scale |
|---|---|---:|---:|---|---:|
| S037 | 横向 4 列 | 170 | 22 | 768 / 770 | 1.000 |
| S037 | 上下 4 行 | 176 | 22 | 770 / 770 | 1.000 |
| S068 | 横向 5 列 | 170 | 22 | 768 / 770 | 1.000 |
| S068 | 上下 | 250 | 76 | 576 / 770 | 1.000 |
| S004 | 横向 3 列 | 176 | 74 | 750 / 770 | 1.000 |

留白下限 `LINGAP = 22`；`linGeo()` 另有字号下限（`idFs ≥ 11.5` / `subFs ≥ 10`），
几何照缩、字不许小到读不出来。

| 范围 | 可见性 | 列表差异 | 操作 |

  点击的假交互。

   `<td>` 一旦变成 flex 盒就不再是 table-cell，Chrome 另生成匿名单元格把它包起来：
   边框只画在文字宽度上（看着就像文件名底下多了一条下划线），盒子也不与同排等高。
2. 7 列没定宽，浏览器按内容抢列：**备注列被压到 48px**（中文一字一行 → 行高 114px），
   整表 813px > 容器 770px，横向还溢出。

**修法**：
- flex 下移到内层 `<span class="dname__in">`，`<td>` 保持 table-cell；文件名
  `overflow-wrap: anywhere` 折行而不截断（截断会吃掉「这是哪一份资料」的唯一信息），
  `title` 保留全名。
- 加 `<colgroup>` + `table-layout: fixed`：资料类型 106 / 文件名 auto（158 起）/
  大小 54 / 归档人 50 / 归档时间 124 / 备注 120 / 操作 158 = 770，正好排满不溢出。
  列宽不是拍的，是**按最长内容实测宽定**：内容超出内容盒时居中的文本会被 Chrome
  左锚、向右溢出，单元格内容中心就与表头中心错开（实测偏 2.8~7.3px）——
  而全局「表头与内容同心 ≤2px」探针正是抓这个。资料类型标签收一档
  （10.5px / 7px 内边距）：7 字「采集与处理记录」按原字号要 100.5px，会把该列撑到 114px。
- 大小 / 归档时间字号 11px + 等宽数字：「2026-03-12 09:30」在 12.5px 下放不进定宽列，
  会折成两行（时间戳折行同样算「格式错乱」）。
- 抽屉底部留 84px 安全区：悬浮球（52px 定在右下 22px、z 90）原本正压住资料表
  最后一行的「移除」按钮。

### 32.1 为什么采集要拆成两段

四个知识域各有自己的结构：临床是**规则表**（编号 / 内容 / 依据）、样本是**溯源链**（三段）、
组学是**关联网络**（三个层面）、文献是**结构化提炼**（类型 / 标题 / 机构 / 等级）。
把这四套模板摞在同一张表单里，用户每次都得先判断「哪一半跟我无关」。

改成先定域，屏上就只剩跟他有关的那一半。**先定域还有第二个好处**：上传方式下每个域该收什么
文件本来就不同（临床收病历 / 指南，组学收表达矩阵 / VCF / h5ad，样本收检测记录表），
accept 与提示都能按域定制 —— 给做组学的人看「请上传病历」和给临床医生看「请上传表达矩阵」一样离谱。

**「手动填写 / 上传」必须是互斥的，不是两个开关。** 它们是两条路径：走了上传，绝大部分手填字段
退化成「补充说明」；两者同时出现时用户没法判断该填哪一份，于是干脆都不填。
所以第 2 屏在选定方式**之前**屏上没有表单，选定之后也只长出那一条路径的字段 ——
断言就长在这上面：手动方式下 `input[type=file]` 必须是 0，上传方式下本域模块必须整块消失。

四域差异模块由 `KBC_MOD` 一张表驱动（`key` 与词条字段同名），采集结果直接落成词条字段，
详情页那套「四域差异化区块」照原样渲染 —— 采什么就能看到什么，不用另写一版展示。

### 32.2 示例数据集设置：三条设置都必须「改完前台立刻看得见」

设置页最容易做成装饰 —— 控件能点、值能存、`localStorage` 里也写着，但前台卡片纹丝不动。
所以这一页的反面要求是：**展示侧与设置侧读同一个 `DEMO_DS` 对象数组**，不是
「设置里改一份、渲染时抄另一份」（抄一份就会在某一版里改走偏，且没有任何断言看得见）。

断言也按这个写：每改一次设置，都把**前台卡片的数量/文字/图片数一起读回来**放进同一次读数 ——
只断设置页自己重画了没有意义（那只是把控件换了个值）。

`DEMO_DS_DEF` 存的是出厂值快照。「恢复默认」这个按钮没有它就只能是个说法。

### 33.1 参考系统那一层是什么样（实测）

链路：项目管理列表 → 操作列「查看」→ **新开一个工作区页**（路由 `/project-detail/profile?…&mode=project-detail`，
面包屑「首页 / 项目详情」，顶部一排多标签工作区），**左栏整条换掉**：

- `项目详情`（页内三页签：项目信息 / 样本信息 / 参考基因组）
- `转录组分析 ▸`（10 个模块：数据质控 / 序列比对 / 基因表达定量 / … / 可视化报告）

模块页的骨架是固定的三段：**顶栏**（分析进度计数 + 当前页分析状态 + 生成报告）→ **横向流程条**
（当前步高亮）→ 该模块的结果表。10 个模块共用同一套骨架，只换内容。

本系统的等价映射（用户拍板两项方向）：三层「项目详情｜分析执行｜分析结果」，模块清单列
**本项目主流程的节点现算**。骨架照抄，内容全部换成本系统的真数据 —— 不另造一套假表。

### 33.2 三层怎么切：页签跟着左栏走

`PDT_HOSTS` 一张表定归属，页签条只渲染**当前这一栏**的那几条：

| 栏 | 页签 | 数量 |
|---|---|---|
| 项目详情 `info` | 项目信息 / 样本信息 / 数据集 / 分析参数 / 参考基因组 | 5 |
| 分析执行 `exec` | 实验流程 / 分析流程 | 2 |
| 分析结果 `result` | 不是页签，是模块清单（横向流程条） | — |

页签条与流程条**共用一个位置但必须互斥**：信息 / 执行两栏下它是页签（回答「这栏里还有哪几块」），
分析结果下它是流程条（回答「我在整条线的第几步、前后各是什么」）。模块有 8～18 个，
塞成页签会溢成两行 —— 这是流程条存在的理由。断言就长在「互斥」上：同时出现是同屏两条导航，
同时消失是没有任何方向感。

`PDTABS` 仍是七个切面的唯一来源，只是多了一张「谁归谁」的归属表；`setProjTab()` 从表里反查分栏，
不由调用方传（传两处必然有一天对不上）。

### 33.3 模块清单与模块页：全部现算

`pdtModules(p)` 三条规则，每条都有理由：

1. **只取主流程**（`projFlows(p)[0]`）。取全部流程的并集 —— P-2026-002 有 21 条流程、节点并集 81 个 ——
   左栏会变成一本字典。主流程才是「这个项目实际跑的那条线」。
2. **剔掉输入类节点**（`输入` / `集合`）。它们是数据来源，不属于「结果」；参考系统那一列里也没有「FASTQ 输入」。
3. **末尾收一个「结果全景」**（定稿名，先前叫「可视化报告」）：流程节点写到出图那一步就停了，
   结果菜单最后得有一个把全部结果收口的总览视图。末节点本身是出图 / 报告类的不重复补。

   > 同名提示（v45 定稿）：p07 那个**独立页面**已整页撤销（v42），「结果全景」现在有两处入口：
   > ① 「分析结果」左栏里的**末项**（`pdtModules()` 补的那一格），点开就是全景正文（`#panoMount`）；
   > ② 项目概况页头的「**查看项目结果全景**」—— 一键直达，且会把当前项目切过去（v28 加、v43 撤过、v44 恢复）。
   > 两处不冲突：第 ① 个是导航（我在哪一格），第 ② 个是动作。但第 ② 个在**已经站在第 ① 格**时会自己隐去（v45），
   > 否则它指向的正是脚下这一格。见 §37。

模块页要回答「这一步产出了什么」。产出与运行记录靠**词元**对齐（`pdtHit`），不靠序号：
产出数据集与日志的名字本来就是按流程步骤起的（`HISAT2 比对结果（BAM）` 对 `HISAT2 比对`、
`MEGAHIT 宏基因组组装` 对 `MEGAHIT 组装`）。对不上就给空态，并**写明缘由**
（「产物并入了下游步骤的数据集」/「在实验流程里跑一次就会留下记录」）—— 空表读起来像加载失败。

模块状态也现算（有失败记录 → 失败 / 有运行中 → 运行中 / 只有成功 → 完成 / 没有记录 → 未运行），
不另写一份状态表：两份状态必然有一天对不上。左栏那一列只放一个字符的记号（`✓ … ! ·`）——
`--rail-w` 的宽度放不下「完成 / 失败」四个字，放进去模块名就被挤没了。

**顶栏那排计数按模块统计**，与页头那排角标（按运行记录条数）不是同一个分母，所以单位写进提示里：
「按模块统计 · 共 8 个模块 · 来自流程「RNA-seq 完整分析流程」」。少了这半句，同一屏上两个
「运行中 1 / 0」会被读成自相矛盾。

### 33.4 修掉的真 bug ①：组学线按 `p.id` 哈希匹配

### 34.1 为什么用 `<template>`，而不是把 DOM 搬过去

「搬进项目详情层」最直白的做法是把那段 HTML 剪到 `#page-projdetail` 里。但要挪 300 行，

`<template>` 让「搬」这件事**不需要移动任何字节**：

- template 的 `content` **不在文档树**里 —— 不渲染、不占位、不受切页与 `innerHTML` 重画的影响；
- 所以它可以**原地**留在 HTML 原来那一段，只是从 `<section class="page">` 降级成 `<template>`；
- 真正要用的时候，`pdtMountPano()` 一次 `cloneNode(true)` 把它挂进 `#panoMount`。

原来的三个入口自然一起失效，这也是撤页必须处理的部分：`build.js` 的 `pages` 清单、
`verify.py` 的逐页循环、`SHOT_PAGE`、以及 `STEPS`（智能分析步骤条 5 步 → 4 步）。

### 34.2 挂载后必须补做的那几件事

内容是静态的，但它**不是自足的**：原来有若干「启动时全站跑一遍」的活儿会顺带照顾到 p07，
搬进 template 之后那些遍历就找不到它了。挂载后必须补：

| 补做 | 不补的后果 |
|---|---|
| `fillTables()` | 富集 / 蛋白组 / 代谢组三张表的 **tbody 是空的**（那三张表体由 JS 填，不像变异表是写死的）。表面上只是「表里没数据」，实际会连锁到导出：`dlFromTable` 见 `rows < 2` 就返回 `null`，三个导出入口**点了没反应** |

`fillTables()` 是 `innerHTML` 覆盖写、幂等 —— 反复进出这一页不会把行叠起来。

v44 让页头跟着左栏走之后，站在「分析结果 › 结果全景」这一格时，大标题与面包屑末段都是「结果全景」，

所以处理方式不是再撤一次按钮（那是把 v44 的决定又推翻一遍），而是**让它跟着当前位置显隐**：
在项目概况 / 分析执行 / 分析结果里的非末格都正常显示，唯独已经站在全景那一格时自己隐去。

### 37.3 判据取「位置」，不取「名字」

最直觉的写法是 `projHeadName() === '结果全景'` —— 会漏。

`pdtModules()` 末尾补「结果全景」是**有例外**的：流程末节点本身就是出图/报告类
（如「物种丰度柱状图」「R 统计出图」）时不补，那一格就叫原名。但按钮跳的仍是它，自指照样成立 ——
按名字判会把这一类项目整个漏掉。

所以判据是**位置**：

```js
function pdtAtPano(p) {                      /* 是否已站在全景那一格 */
  if (PDSEC !== 'result' || !p) return false;
  var mods = pdtModules(p);
  return mods.length > 0 && PDMOD >= mods.length - 1;
}
```

「是不是最后一格」是位置事实，与它叫什么无关。`>=` 而不是 `==`：越界（换项目后旧下标）时也归到末格，
不会因为 `mods.length - 1` 变小而漏判。

### 37.4 显隐只切 `hidden`，不重画操作条

`#projActs` 里除了这两颗按钮，还挨着一排状态徽章（数据集 / 运行中 / 成功 / 失败）。
重画整条操作条会连徽章一起闪 —— 所以按钮**常驻 DOM，只切 `hidden`**。

- **生成**：`renderProjHead()` 里给按钮加稳定 id `#projPanoBtn`；函数末尾补一次 `markProjPano()`
  （重画后是**新节点**，新节点默认没有 `hidden`，不补这一下会先露一下再被隐掉）。
- **刷新**：`markProjPano()` 挂在 `renderProjTitle()` 末尾 —— 那正是 v44 建好的
  「进页面 / 切栏 / 切模块 / 切页签」四处唯一挂点，所以一处挂上四处生效。

**CSS 必须补一条**：`.pd__act .btn[hidden] { display: none; }`。

`.btn` 是 `inline-flex`，UA 的 `[hidden] { display: none }` 压不住类选择器，而 `.pd__act` 自己又是
`display: flex` 的容器。文件里本来已有一条 `.phead__side .btn[hidden]` —— 但 `#projActs` 是 `.pd__act`、
**不在** `.phead__side` 里，照抄那条的适用范围正好漏掉它。漏了的表现是：按钮 `hidden` 了却依然躺着，
看着像「没生效」，而断言若只读 `hidden` 属性还会照样绿。

```js
var KBC_MOD = { clin: { t: '标准化临床实践规则', i: 'list-check', ... } };   // 变量引用，扫描器看不见
```

`list-check` 在源码里本来是**靠别处的巧合**才被内联的：`renderGeneRebuild()` 里写着一句
字面量 `ico('list-check')`（「重建范围」那一格），build.js 的扫描器扫到的是**那一处**。
本系统压根没有人手写 `ico('list-check')` 给知识采集用。

那处字面量一删 → 名字只剩 `ico(m.i)` 这种变量引用 → 扫描不到 → `ico()` 走占位分支。
而占位符是把路径数据**当文本**塞进 `<svg>` 的：


于是 `.kbc-mod__hd` 的 `textContent` 变成「`M256 8a248 248 0 1 0 …` 标准化临床实践规则」，

比 `<缺失>` 更绕，因为它看起来像**内容**问题，不像图标问题。

**修法不是改断言，是把名字补进 `ICON_REGISTRY`** —— 那张表的职责就是这个
（「凡 `ico(变量)` 的数据源都必须落在本表里」），并在注释里写清这次为什么才补上。
补完 `node build.js` 回到 **105 个**，与 v45 逐名一致。

> 教训：**删代码前问一句「我删掉的这段里，有没有哪一处是别人唯一的存在理由」**。
> 对图标名来说，这个「理由」就是字面量出处。可复现的检查法：用 build.js 的同样两条正则
> （`fa-solid fa-([a-z0-9-]+)` 与 `ico\('([a-z0-9-]+)'`）扫一遍改前/改后的源码 + `ICON_REGISTRY`，
> 两边取差集 —— 差集里出现「仍在被变量消费」的名字，就是漏登记。

### 39.2 需求 2：新建项目向导 4 步 → 6 步

用户的原话是「整个新建项目需要与目前实际的创建分析流程相匹配」。本系统真实的建流程动作是：

而 v39 收敛后的向导是「项目信息 → 数据文件 → 分组与比较方案 → 创建完成」——
中间那两步**被整个跳过去了**：于是「建完之后这个项目要跑什么、按什么参数跑」，
向导里一个字都没问。补回之后：

| # | 步骤 | 内容 | 落库字段 |
|---|---|---|---|
| 1 | 项目信息 | 名称 / 描述 / 项目组 / 样本多选 / 参考基因组 / 实验条件 | `name` `desc` `grp` `sids` `ref` |

| **5** | **参数配置** | **左表单 12 个控件 + 右实时摘要** | `params` |
| 6 | 创建完成 | 回执（进这一步就落库） | `made` |

### 39.3 需求 3：系统管理 › 项目组管理

**它要解决的问题是「同一个名单有三个来源」。** 改动前，「项目组」只是三处写死的字面量：

- 向导第 1 步的 `PNEW_GROUPS` 数组；
- 文件管理「团队文件」上传时的两个硬编码名字；
- 项目记录上的 `tags`。

于是「谁能被选到」这件事**没有任何地方能管**，也没有「谁在管 / 审没审 / 启没启用」。
现在合并成一份数据 `PROJ_GROUPS` + 一个页面：

| 项 | 设计 |
|---|---|
| 数据 | 7 条，字段 `id / n / members / on / st / created / own` |
| 三态 | `on`（启用，控制**是否出现在选择项里**）· `st`（`pass / pending / reject`，审核结论，**本页只读**）· 操作权限 |
| 归属 | 新建项目第 1 步 + 文件管理团队上传，**读同一份** `pgPickNames()`（= `on && st === 'pass'`） |
| 表 | 9 列：全选 / 名称 / 成员（头像+名字堆叠，多的折 `…`）/ 人数 / 项目组状态 / 创建时间（可排序）/ 状态 / 创建人 / 操作 |
| 工具条 | 创建 / 删除 / 已选计数 / 搜索（名称 + 成员）/ 刷新 |
| 排序 | 三态循环：原序（新在前）→ 创建时间升序 → 降序 |

为什么「删除」只对**已驳回**开放（不是「已通过的也能删」）：

- 待审核的组可能马上通过 —— 删早了要重走一遍申请；
- 已通过的组很可能**已经被项目 / 文件引用** —— 删掉会让那些东西的归属悬空；
- 只有已驳回的组确定不会被采用，删掉不影响任何历史数据。

为什么新建的组一律 `st: 'pending'`：**自己说自己通过等于没有审核这一环。**

**权限分三档，管理员 / 项目负责人可写，普通成员只读。** 页头的身份开关是这一页
唯一的权限入口；注意它是**组织身份**，与顶栏那个「视图角色」（临床医生 / 生信工程师）
不是一回事 —— 后者决定界面上露哪些控件（`.cli-only` / `.eng-only`），
前者决定有没有权限动东西，项目组的增删改只认前者。

权限的「挡」有三层，缺一层就等于没挡：

1. **视觉**：只读身份下操作列整列变成「只读」，行内编辑 / 删除按钮一个都不渲染；
2. **状态**：行勾选框、启停开关、全选框、以及「创建项目组」全部 `disabled`；
3. **委托分支**：`data-pg-*` 的每个分支里**自己再判一次 `pgCanWrite()`**。
   为什么必须有第三层：键盘、脚本、以及将来别处冒出来的入口都会绕过视觉态，
   只有分支里挡一次是可信的。验证脚本专门为此走了一条「脚本绕过视觉态」的用例 ——
   工具条那颗「删除」只是 `aria-disabled`（不藏起来是有理由的：藏起来用户不知道
   有没有这个能力），脚本照样点得动，它必须给出理由而不是默默不动。

### 39.4 本轮踩到的三个坑

**① 一个 `id` 写错了，但一直没人看见。** `renderProjGroups()` 往 `#pgDel` 上写

### 40.2 需求 2：子编辑器的「返回」

### 41.1 这不是「加回来」，是把一页从一份名单里摘掉

根因只有一行 —— `goto()` 里的：

```js
if (!RAIL_LOCK) setRail(!(id === 'sample' || id === 'log'));
```

这是「宽表页自动收左栏、把宽度让出来」的实现。运行日志的主内容确实是宽表（6 列：
时间 / 用户 / 类型 / 状态 / 项目 / 内容），当初因此把它放进了名单。

问题在于**它同时是「系统管理」组里的一个菜单项**：到了这一页左栏自动收起，
连它自己那一格的高亮一起消失。用户看到的就是「整页进了全屏、菜单不见了」。

这份名单历史上被摘过两次，理由都是同一条：

| 版本 | 摘掉 | 为什么 |
|---|---|---|
| v28 | `proj` | 项目管理在「项目空间」组里，是菜单项 |
| v40 | `dataset` | 它已不是页面，宽表改在项目概况页签里 |
| **v49** | **`log`** | 运行日志在「系统管理」组里，是菜单项 |

于是规则可以写清楚了：

> **菜单里有的页，不自动收左栏。**

因为左栏同时回答两个问题 ——「我在哪」与「我能去哪」。一个页面在到达时把自己的导航
藏起来，等于两个问题一起失去答案；**要收，由用户点收起按钮（`[data-rail-toggle]`）决定**，
`RAIL_LOCK` 的语义不变。

名单里至此只剩 `sample`（样本管理）：它**不在**左栏菜单里（用户回复「另安排」），
主内容又是宽表，收起来不影响任何一格的高亮。**它哪天进菜单，就要从这一行里摘掉** ——
这句话写在 `goto()` 的注释里（代码旁边），而不是只写在本文里。

### 42.2 数据汇集页：两栏选择器，与文件管理 / 向导第 2 步**同源**

#### 42.5.1 一条应该早一点立好的口径：截图**不逐位比对**

本轮两轮回归的截图 md5 对不上（14 张），一度被当成「改动外溢」的信号。实测把它定位了：

> 短探针在同一会话内对 p01 隔 **70 秒**重拍两张 → **342 个像素不同**，且散落在整个内容区；
> 同一刻的**项目管理列表逐位一致**（那张页上没有旋转图标）。

原因是站内有一类**持续动画**：

```css
@keyframes wb-spin { to { transform: rotate(360deg); } }
svg.spin { animation: wb-spin 1.1s linear infinite; }
```

「运行中」「智能体思考中」这些指示都是它在转，**拍到哪一帧是随机的**。

（工作台、项目管理、运行日志、编排区、智能体浮窗…），不是本轮改动的产物。

> 口径：**别拿截图 md5 当「零外溢」的硬证据** —— 它只对「页面上没有任何 `svg.spin`」的图成立。
> 要真想要逐位可比，得在截图前统一注入 `svg.spin { animation: none }`
> （CSS 里已经为 `prefers-reduced-motion` 预留了同一条开关），本轮**不做**，只把这条记下来。
> 顺带：v49 §41.3 里那个「77/78 与 v48 值不同」的未定位差异，多半也是这一条 ——
> 向导弹窗上同样挂着运行中图标。

- 一条写进注释的经验，正好与「撤功能要连它的引用一起撤」互为镜像：

  > **「撤功能时顺手把探针删掉」= 这个功能从此再也守不住。**
  >
  > `navSubNums`（「智能分析二级不再带步骤号」）在该组不上菜单之后
  > **已经量不到东西**，留着只会常红、且无法修。正确姿势是**换个位置继续守** ——
  > 它守的事被 `navBadges` 接过：从「盯一个组」升级成「盯整条左栏」，
  > 比原来更严。撤一个东西时要问两句：哪些**引用**要跟着删（会抛错），
  > 哪些**守卫**要跟着搬家（不搬就悄悄失守）。

## 43 · v51：智能分析补第 5 步「查看分析结果」

### 43.1 这一步为什么该回来

v42 把「结果全景」从这条线上撤掉，降级成项目详情里的一层。当时的理由写在 §34：
那时的判断是「一条分析线到『任务运行』就算走完了，结果属于项目，去项目里看」。

那个判断在真实使用里站不住：**任务跑完，人接下来要做的恰恰是「看这批数据算出了什么」**，
而不是先退出这条线、回项目列表、再钻进去找。

> 一条线的终点应该落在「这件事做完了」，而不是「系统开始干活了」。
> 「任务运行」是过程的最后一屏，「查看分析结果」才是结论。

所以本轮把结果那一步以「查看分析结果」的名字请回来，`STEPS` 由 4 步变 5 步。

### 43.2 一份内容、两个宿主

**没有复制那份结果全景。** 它原地住在 `<template id="panoTpl">`（300 行静态标记、

| `#resMount` | 智能分析第 5 步 › 查看分析结果 | `goto('p07')` 时 |

> template 里带着 `#viewSeg` 与三张空表体的 id，两份同时进文档树就有两个同 id 元素：

它身上挂着一道闸：「任务还没结束」时点了要拦住，不能跳页。

v51 再搬进 `[data-res]`。漏搬的后果不是「按钮灰着但点得动」这么轻：
人已经站在结果页上，看的是**上一批**数据的结果。

> 闸认的是「按钮 id + `aria-disabled`」这一对事实，而不是它挂在哪个属性上。
> 所以搬家时它必须整体平移，不能只改属性名。

另外两个入口：

- **任务运行页的页脚**多了一格「下一步：查看分析结果」。它和那颗按钮是同一件事的两个入口，
  区别在于**页脚这颗不受任务状态影响** —— 任务还在排队时按钮是灰的，页脚照样走得下去。
- 项目详情里那两颗「查看结果」（任务结果表的每一行上）**仍走 `data-pano`**：
  用户此刻站在项目层的语境里看待这份结果，点一下又跳去智能分析线是两套语境串台。

## 44 · v52：智能分析简介改口径 + 「运行分析」先补项目信息

**需求原文**：① 智能分析的简介：把「不建项目，直接进分析工作台」修改成为
「自定义自编排工作流」；② 在最后一步点击「运行分析」时弹窗出现**完善项目信息**的弹窗
（项目名称、项目描述、所属项目组、样本ID（自动回填）、样本描述信息、参考基因组（自动回填）、
实验条件等），点击确认后进入分析流程。

### 44.1 简介为什么改口径

旧文案把「不建项目」当卖点说。但 v51 把第 5 步补回来之后，这条线已经是
「数据汇集 → 流程模板 → 参数配置 → 任务运行 → 查看分析结果」的**完整五步** ——
它的特征不再是「少了什么」（不建项目），而是「流程由你自己编排」。
新简介顺着这个说法写，步数说明也跟着 v51 的 `STEPS` 走（5 步）。

> 「不建项目」说的是**它不是什么**；「自定义自编排工作流」说的是**它是什么**。
> 一条产品线的简介应该用第二句。

### 44.2 「运行分析」为什么先弹窗

这条线不建项目就直接跑。走到「运行分析」那一刻，**这批数据属于谁、用来做什么，
系统里一个字都没有** —— 结果跑出来没人认得它是谁的。

所以 v52 在参数配置页的「运行分析」（`#btnRunAna`）上挂了一个新分支 `data-runmeta`：
先弹「完善项目信息」，确认之后才进任务运行页开跑。**顺序是刻意的** ——
信息先落、再开跑；反过来（先跑起来再补）跑出结果那一刻系统里还是没有归属。

挂点从 `[data-run]` 换成 `[data-runmeta]` 也是刻意的：留在原地会和任务运行页那颗
「开始运行」（`#btnRun`，重跑入口）共用一条分支，而两者要做的事已经不同了。
`[data-run]` 全站只剩 `#btnRun` 一个，这条注释写进了代码里防止误改。

### 44.3 七项怎么分：四项人填、两项回填

| 字段 | 谁定 | 为什么 |
|---|---|---|
| 项目名称 / 项目描述 / 所属项目组 / 样本描述信息 | **人填，必填** | 系统推不出来 |
| 样本ID | **自动回填，只读行** | 数据汇集选的数据已经决定了它 |
| 参考基因组 | **自动回填，只读行** | 数据汇集 › 参考基因组已经决定了它 |

- **回填行不做成 disabled 的输入框**（`.rbfill` 虚线框 + 品牌浅底）。disabled 的

- **项目组下拉与向导第 1 步同源**（都走 `pgPickNames()`：已通过 + 启用的组）。
  两处各写一张名单，迟早出现「向导里有、这里没有」的分叉。

## 46 · v54：角色体系收敛为三档（超级管理员 / 普通管理员 / 普通用户）

### 46.1 需求

三条，来自同一段话：

1. **角色改为三档** —— 超级管理员（超级管理员 / 信息科 / 样本库负责人，所有权限）、
   普通管理员（主管 / 知识库管理员 / 项目负责人，增删改查 / 审批）、
   普通用户（普通用户，查看 / 新增）；
2. **撤掉顶栏「临床医生 / PI ⇄ 生信工程师」那对切换器**；
3. 改成**点顶栏「当前用户」即可切换角色**的演示效果。

### 46.2 关键判断：原型里原有**两套**角色，不能直接改一套

改之前先把既有事实摸清，否则会「换了个名字，权限一位没动」：

| 旧角色 | 位置 | 真实作用 |
|---|---|---|
| 临床医生 / PI ⇄ 生信工程师 | 顶栏 `.rolesw` 切换器 | **视图**：只切界面露哪些控件（`.cli-only` 5 处 / `.eng-only` 9 处）—— 参数面板细节、日志默认收起或展开、格式字段。**完全不改权限** |
| 管理员 / 项目负责人 / 普通成员 | 项目组页页头 `[data-pg-role]` | **权限**：`pgCanWrite()` 决定项目组能否增删改 |

并存的问题很实在：**切了视图切换器，任何权限都不会变**，人分不清哪个才是自己的身份；
同一件事两个入口，改一个另一个不同步。

v54 的解法是**合并为一档**：角色即身份，视图差异由角色顺带决定
（普通用户看不到 `.eng-only` 那批工程细节，两档管理员都看得到）。

### 46.3 改动

**① 角色名单（app.js，全站唯一来源）**

```js
var ROLES = [
  { k:'super', n:'超级管理员', who:'超级管理员 / 信息科 / 样本库负责人', ico:'shield-halved', p:'所有权限' },
  { k:'admin', n:'普通管理员', who:'主管 / 知识库管理员 / 项目负责人',   ico:'user-gear',     p:'增删改查 / 审批' },
  { k:'user',  n:'普通用户',   who:'普通用户',                          ico:'user',          p:'查看 / 新增' }
];
```

权限判定一律走三个函数，渲染里不再出现 `role === 'xxx'` 字面量：
`canManage()`（增删改查 / 审批，= super | admin）、`canConfig()`（系统级配置，= super）、
`isBasic()`（普通用户）。`pgCanWrite()` 保留原名，内部转调 `canManage()` —— 调用点有 8 处，
改名只会制造无谓的 diff。

**② 顶栏：一处身份入口**

`.rolesw` 整组撤除（HTML + CSS 三条规则 + verify 的读数组），换成 `#userSw`：
图标 + 角色名 + 职能副标 + 下拉；菜单 `#popUser` 里三个角色，每条写清「它是谁 + 能做什么」。
`setRole(k)` 是唯一入口，一处改、四处跟着变：顶栏文案、`body[data-role]`、
三个受权限影响的页面（`renderProjGroups` / `renderKb2Admin` / `renderDemoSet`）、
菜单高亮。少刷任何一处，都会留下「顶栏写着普通用户、按钮还能点」的残影。

`body[data-role]` 挂在 body 上而不是按钮上 —— CSS 靠它决定 `.eng-only` 露不露。
取值从 `clinician/engineer` 换成 `super/admin/user`，旧规则

```css
body[data-role="clinician"] .eng-only,
body[data-role="engineer"] .cli-only { display: none !important; }
```

换成一条 `body[data-role="user"] .eng-only { display: none !important; }`。
`.cli-only` 这层「临床视角」概念整体作废 —— 它承载的推荐配置卡、日志展开按钮
是人人该看到的东西，不再需要任何隐藏规则。

**③ 三处权限门**

| 门 | 规则 | 表现 |
|---|---|---|
| 项目组治理 | `canManage()` | 普通用户：勾选框 / 启停开关 / 新建按钮真 `disabled`，操作列「只读」，页脚与页头徽标说明谁才能改 |
| 知识审批 | 流转动作分两类：「提交审核」（draft→review）属新增流程，**所有角色可用**；审核发布 / 归档 / 修订 / 恢复是**审批**，`canManage()` | 普通用户：审批按钮禁用 + `#kbmAprHint` 提示条说明该找谁 |
| 示例数据集配置 | `canConfig()`（仅超级管理员） | 两档管理员以下：9 个开关 + 3 颗工具条按钮真 `disabled`，`#pubdsPerm` 提示条 |

三处都遵守既有铁律：**权限不足不隐藏控件，只禁用并说明原因**（隐藏会让人以为功能没做）。
且视觉态之外，**事件委托里都有第二道同样的判断** —— 脚本与键盘绕过按钮状态也挡得住。

**④ 连带清理**

| B 整组换成单个外链入口 | 口径最干净（不出现两个知识库），但内容量大幅缩减，多处引用要连带改 |
| C 保留子页另加一条外链入口 | 原结构零改动，但左栏多一项，与「组标题即入口」的意图有偏差 |

**已选 A。** 理由：知识库已有独立成型的业务系统（`package2/kb`），站内三页作为「说明与展示」继续保留；组标题则成为进入真实系统的主入口——两者并存，不互相取代。

打开方式选「新标签页」：外链跳走再「后退」会丢掉原型当前的上下文，新标签能并排对照。

### 49.3 关键实现：把一个 `<button>` 拆成「链接 + 按钮」

原来分组标题是一个 `<button class="snav__grp">`，整体可点，点击 = 展开/收起。现在要「点文字跳外链、点箭头折叠」，**同一个元素承担两种互斥行为**是不可能的，必须拆。

**不能把 `<a>` 塞进 `<button>`** —— 非法嵌套，且外链会带上按钮语义（读屏念成「按钮」而不是「链接」）。所以结构改为：

```
<div class="snav__grp snav__grp--split">        ← 降级为行容器
  <a class="snav__ext" target="_blank" …>        ← 外链文字区（真实锚点）
  <button class="snav__chevBtn" data-navgrp>    ← 折叠能力在这里
</div>
```

**为什么用真锚点而不是 `click` 里 `window.open`**：真锚点自带键盘 Enter、右键「在新标签页打开」、「复制链接地址」、Cmd+点击开新标签等原生能力；用 JS 模拟这些全都要手写，且十有八九漏掉。

**`aria-expanded` 必须留在箭头上**（不能挂到 `<a>` 上）：链接不该有「展开列表」的语义，挂了是读屏会读错的无障碍错误。

### 49.4 三条实现细节

| 项 | 做法 | 理由 |
|---|---|---|
| 地址登记 | `NAVGROUPS[].ext` 字段（唯一事实来源） | 换地址只改一处，不散落在事件委托里 |
| 外链标记图标 | `arrow-up-right-from-square`，默认 `opacity:0`、悬停显形 | 不给左栏增加常驻色块；但语义上标明「这是站外入口」 |
| `rel="noopener"` | 必带 | 否则新页可通过 `window.opener` 反向操纵本页 |

CSS 侧：`.snav__grp--split` 去掉自身 hover 底色（否则箭头块与文字块之间出现底色断缝），改由内层两块各自承担。

### 49.5 build 自检判据的精度修正（不是放宽）

build 自检原本用「产物文本里出现任何 `http://`」判「离线版存在外部请求」。v57 引入外链后它开始报假告警——但这条告警**不是错的，是判据太粗**：它把「用户点击才发起的导航」当成了「页面加载即发起的请求」。

按发起时机拆成两类：

| 类别 | 判据 | 期望 |
|---|---|---|
| 加载即发起（`src=` / `url()` / `@import` / `link href`） | 必须为 0 —— 离线单文件的价值就在这 | 0 |
| 用户点击才发起（`a[href]` / `NAVGROUPS.ext`） | 允许，但要有白名单 | 唯一一项 |

折中判据**不是「再补几条正则」**（那只会漏得更隐蔽），而是**按语义定位**：站外地址只允许出现在 `a[href]` 与 `ext` 数据字段两处，把这两处整段摘掉后，剩下任何 `http://` 才是真问题。

配套加两条反向检查：`ext` 数据里出现未登记的站外链接 → 报；白名单项没出现在产物/数据/模板任一处 → 报（「只改了数据没接上入口」是这类改动最常见的半吊子形态）。

> 顺带一个认知修正：**「产物文本里证明不了 a[href]」** —— 外链是**运行时**由 `NAVGROUPS.ext` 拼出来的，静态 HTML 里只有 `href="' + esc(grp.ext) + '"` 这样的模板。所以「页面上真的有这个可点入口」只能由**运行时探针**断，静态检查一律断不了。

### 49.6 验证：6 条新断言 + 一个必然踩的坑

新增运行时探针 `R.kbExt`（**不点外链** —— 目标是内网地址，点开会真发起请求并挂起，污染后续所有读数），断言：

| # | 断言 | 要点 |
|---|---|---|
| 1 | 是真实外链 `<a>`，地址与需求一致，全站唯一 | `linkN == 1`，防止以后又塞一个 |
| 2 | 新标签打开 + `rel="noopener"` | 安全缺口 |
| 3 | 外链区带标记图标 | 不内联就渲染成问号占位 |
| 4 | `aria-expanded` 只挂箭头、没挂到外链上 | 拆结构最容易犯的无障碍错 |
| 5 | 3 个子页一个没少 | 外链是「多一条路」不是「替掉原来的」 |
| 6 | **点箭头仍能折叠 / 展开** + 用完已还原 | 只读属性证明不了「点了会响应」；还原本身也要断 |

**第七次踩同一个坑**：verify 里有 12 处 + 2 处截图 setup 用 `.snav__grp[data-navgrp="知识赋能"]` 选分组标题。`data-navgrp` 搬到箭头后这个选择器匹配不到任何东西 → `q()` 返回 `null` → `getAttribute` 抛错 → **整段驱动被打断，其后几百条读数全成 `<缺失>`**。

修法要点：**点击后必须重新取节点**。每次 click 都触发 `renderNav()` 重画整条左栏，旧节点全部失效 —— 把节点存进变量跨一步就是那个 bug 本身。

> 截图 setup 写错选择器是**静默失败**（只表现为 md5 变化，很难归因），所以那 2 处一并改成按文字定位、对拆分前后两种结构都成立。

## 50 · v58：知识赋能三页 → 页内挂载外部知识系统

### 50.1 需求

用户提出：「接入这个链接 `http://192.168.77.144:20080/package2/kb?menu=1`，**换一种接入方式** —— 把原先的『医学知识库』『自有知识库』和『知识图谱』直接对接到 77.144 的三个独立路径，分别是 ke、kb 和 kg。把 menu 参数去掉，然后在右侧工作区展示外部页面（保持左侧菜单布局）使外部接入部分和当前系统更像一个整体。」

这是对 v57（组标题跳外链）的**方案替换**，不是补充。

### 50.2 先验证可行性：iframe 能不能挂

跨域 iframe 有个绕不过的硬约束 —— 外部系统可以用 `X-Frame-Options` / `Content-Security-Policy: frame-ancestors` **拒绝被嵌套**，而那是响应头，前端无解。

实测三个路径（`curl -D`）：

| 路径 | 状态 | Content-Type | X-Frame-Options | CSP |
|---|---|---|---|---|
| `/package2/ke` | 200 | text/html | **无** | **无** |
| `/package2/kb` | 200 | text/html | **无** | **无** |
| `/package2/kg` | 200 | text/html | **无** | **无** |

三者是同一个 Vite SPA（`Knowledge Frontend`），靠**前端路由**区分视图 —— 所以路径决定内容，iframe 挂各自的即可。

> 顺带一个发现：带 `?menu=1` 时旧探测**不通**，去掉参数后 200 —— 印证了「去掉 menu 参数」这条要求本身就是必要的，不是顺口一提。

**这条验证放在动手之前**：如果对方已下发 `X-Frame-Options`，整个方案不成立，那就得换别的做法。**先验证前提，再动手** —— 这是本轮最值钱的动作。

### 50.3 关键判断：两条取舍

**① iframe 而不是跳外链。** 需求明确说「保持左侧菜单布局」「更像一个整体」—— 跳外链会把整站布局整个丢掉，恰恰是最不像整体的做法。iframe 让外部能力长在站内壳子里：左栏、面包屑、顶栏、页头全在。

**② 站内那份保留，不整页替换。** 这三页已建得很完整（医学知识库 58 词条 / 四域 / 三模式 + 审批流、知识图谱画布、自有知识库上传解析），背后是 270 行 HTML + 上千行 JS + verify 里 24 条断言。整页替换会让这些能力从原型里消失，且内网地址在别人机器上不通时，三页直接变白板。

与用户确认后定的方案：**页头加「外部系统 / 站内版本」切换**，两个内容来源都在。

### 50.4 实现

**地址唯一事实来源**（换服务器只改一处）：

```js
var KB_EXT_BASE = 'http://192.168.77.144:20080/package2';
var KB_EXT = {
  kbmed:   { path: '/ke', name: '医学知识库' },
  kbown:   { path: '/kb', name: '自有知识库' },
  kbgraph: { path: '/kg', name: '知识图谱' }
};
```

**视图切换用 `hidden` 收放，不换页** —— 换页会丢滚动位置，面包屑也会多出一级。

**加载失败态必须有真实退路。** 这是本轮第二个值得记的点：iframe 的 `load` 事件在**被拒绝时根本不触发**（`X-Frame-Options` 拒绝、连接失败、DNS 不通都是直接拒绝），所以「没等到 load」本身就是失败信号 —— 必须有 `setTimeout` 兜底（8 秒），否则失败态永远不显示，用户只看到一片空白，连「是我网络问题还是系统坏了」都判断不了。失败态给的是**真实可点**的「重新加载 / 新标签打开」，不编造占位内容。

「重新加载」用 `removeAttribute('src')` + 下一帧写回 —— 直接改同一个值浏览器可能不再发请求。

### 50.5 撤掉 v57 的那套

v57 的「组标题拆成外链 + 独立箭头」整段不再需要，随之撤除的还有 `.snav__ext` / `.snav__extico` / `.snav__chevBtn` / `.snav__grp--split` 一整套 CSS 与 `NAVGROUPS.ext` 字段。

**留着的只有 `.snav__grp` 类本身** —— verify 的 `R.ia.navGroups` 靠它数4 组，改名整条断言会红。

### 50.6 踩坑三则

**① 选择器撞名。** 我给 iframe 区用了 `data-kbopen`，而知识图谱面板里早就有 `q('#kbPanel [data-kbopen]')` —— 撞名后那个选择器会同时命中两处。改名 `data-kbframeopen`。

> **给探针/钩子加字段前先 grep 那个键**，撞名会静默覆盖，比「读不到」更难查（项目记忆里已有此条，本轮再次印证）。

**② 既有断言全押在站内视图上。** 三页默认视图改成 `ext` 后，那24 条知识库断言全部会落空 —— 而且失败原因会指向「词条少了」这种完全无关的方向。修法：在知识库采集段**开头统一切 local、段末切回 ext**。

**③ 视图状态是共享页内状态。** `KBMODE` 跨页共享，探针切了不还原会污染后面几十条断言 —— 已有 `__kbView(id, view)` 探针，段首段尾各调一次。

### 50.7 build 自检的适配

v57 建的「站外地址白名单」判据要跟着变：

- iframe 的 `src` 是**动态 `setAttribute` 赋值**的，产物 HTML 里**根本没有 src 属性** —— 所以「加载即发起必须为 0」那条判据依然成立。
- 白名单从「一条 `?menu=1` 外链」改为「`KB_EXT_BASE` 一个常量」，并加两条反向检查：三个路径 `/ke` `/kb` `/kg` 都要在 `KB_EXT` 里；挂载实现的三个关键片段（`data-kbframe` / `data-kbframeel` / `initKbFrames`）都要在产物里 —— **只有地址没有模板 = 改了配置但页面上不会出现 iframe**。

### 50.8 验证：8 条新断言

新增运行时探针 `R.kbFrames`（三页各采一次）+ `R.kbSwitch` / `R.kbSwitchBack`（切视图来回）。

| # | 断言 | 要点 |
|---|---|---|
| 1 | 三页各自挂 ke / kb / kg | 路径必须与需求一一对应 |
| 2 | **已去掉 menu 参数** | 漏改不会报错，只会静默多传一个参数 —— 需求明确要求的动作必须钉住 |
| 3 | 挂的是 iframe 不是跳外链 | `tag == 'IFRAME'`，JS 里 `window.open` 一样断 |
| 4 | 默认停在外部视图，站内那份收着 | `hidden` 而不是删掉 |
| 5 | 失败有真实可点的退路 | 重新加载 / 新标签打开各 ≥2 处 |
| 6 | 可切站内，内容还在 | `localRows > 0` |
| 7 | 切视图不改地址 | `srcKept` 原样保留 |
| 8 | 切回 ext 还原 + `aria-selected` 跟着走 | 读屏一致性 |

**刻意不断言「iframe 加载成功」**：跨域读不到内容，目标又是内网地址，成败取决于**跑验证的这台机器有没有接内网** —— 那是环境不是缺陷。写进断言等于给回归埋一颗「换台机器就红」的雷。

## §51 v59：修复内置数据集封面图裂（构建期键名被替换）

### 51.1 现象与定位

用户报「工作台的内置数据集封面图不显示了」。按 `demoCoverHTML() → resolveImg() → assetAbs()`
这条链路逐段查，最后在**构建产物**里定位到：

```js
// 产物中实际的 IMG_URI（错的）
window.IMG_URI = {
  "data:image/jpeg;base64,/9j/4AAQ…": "data:image/jpeg;base64,/9j/4AAQ…",  // ← 键被替换了
  …共 6 条，键全部是 base64
};
```

`app.js` 的 `assetAbs(p)` 是 `window.IMG_URI['assets/' + p]` —— **键名必须是相对路径**。
键变成 base64 后查表必然落空，于是 `|| k` 退回相对路径 `assets/dataset-wgs.jpg`。

### 51.2 根因：注入时机与替换顺序反了

`build.js` 原本的顺序是：

1. 先把 `window.IMG_URI={…}` 注入产物（键 = `assets/xxx.jpg`，值 = base64）
2. **再**做「`assets/xxx` → base64」的 split-join 替换

第 2 步的替换是**全文档字符串替换**，它连第 1 步刚注入的**键名**一起换了 ——
这正是注释里当初想避开的情况（「build 会把 HTML 里的 assets/xxx 路径替换成 base64」），
但只防住了 HTML 与 JS 源码，**没防住映射表自己**。

### 51.3 为什么本地看不出来、线上才裂

`prototype/` 目录里 `assets/` 就在旁边，相对路径照样能出图 → 本地开发与回归全绿。
`deploy-static/` 只有 `index.html` 一个文件，**没有 `assets/`** → 封面全裂。
「查表失败就退回相对路径」这个静默降级，把一个构建期缺陷伪装成了部署环境问题。

### 51.4 修法

**① 调整注入时机**（离线版与 CDN 版都改）：注入处只埋 `<!--INJECT_IMG_URI-->` 占位，
等所有路径替换做完，再用**函数式 replace** 回填映射表。

```js
offline = offline.replace('<!--INJECT_JS-->', () =>
  '<!--INJECT_IMG_URI-->\n<script>window.FAI=…</script>\n<script>\n' + jsRaw + '\n</script>');
/* …替换 assets/xxx → base64… */
offline = offline.replace('<!--INJECT_IMG_URI-->', () => injectImgUri(IMG_DATA));
```

**② 顺带修好 CDN 版**：原来 `index-cdn.html` 的 `IMG_URI={}` 是**留空**的，
注释写「asset() 会退回 assets/ 相对路径，配合 CDN 图源仍能显示」—— 这个推断是错的：
远程 URL 是构建期拼出来的，运行时那串相对路径**没有任何东西会替换它**，
所以 CDN 版的封面同样图裂。改为直接注入远程 URL 表（`IMG_REMOTE`）。

**③ base64 只算一次**：原先内联循环与映射表各读一遍文件，改为共用预计算的 `IMG_DATA`。

### 51.5 补上能断住它的断言

原来的自检 `off.includes('"' + k + '"')`（查 HTML 里有没有相对路径）**抓不到这个 bug** ——
键名被替换后产物里 `assets/xxx` 一个都不剩，那条检查反而认为「已内联干净」而全绿。
换成直接解析映射表并校验：键名是否完好、条目数是否相符、值是否 data:（离线）/ http:（CDN）。
**「查表命中 0 就静默降级」的故障类型，必须断查表本身，而不是断降级后的产物。**

verify.py 侧补 3 条运行时断言（新增 `__pubds()` 探针读数）：
- `imgUriKeys` / `imgUriKeyAllPath` —— 6 条键名全为 `assets/`
- `resolveHit` —— 3 个内置封面短键全部命中映射表（不退回相对路径）
- `coverSrcKinds` / `coverLoaded` / `coverSize` —— `<img>` 真实 `naturalWidth > 0`，
  且 src 前缀为 `data:`（证明走的是映射表而非相对路径）

**要点**：v40 那条断言只数 `.dcard__im` 元素个数，而元素**一直都在**（只是图裂），
所以断不出来。**「有元素」≠「有图」，「元素数对」≠「图能显示」。**

### 51.6 副产物

映射表不再被二次膨胀（每个键原本都是一份完整 base64），产物从 5,571,647 → **5,240,249** 字节，
减少约 33 万字节。

### 51.7 还原点

`_backup-v1/v59-imguri/`（src ×3 + verify.py + build.js）。

## §52 v60：流程编排区接入外部编排系统（全屏进入）

### 52.1 需求与方案取舍

需求原文：「把 `http://aizx.jwzcloud.com:1888/` 这个链接放入到项目管理-智能分析-
流程编排页面中，点击自编排的全屏按钮，进入此链接页面」。

「进入此链接页面」有三种做法，选了**全屏 + 页内嵌入**：

| 方案 | 取舍 |
|---|---|
| 新标签打开 | 整站布局（顶栏/左栏/面包屑）全丢，回来只能靠浏览器后退 |
| 当前页整页跳转 | 同上，且浏览器后退会把整站状态一起带走 |
| **全屏 + 页内嵌入** | 面包屑、左栏、顶栏都还在；进得去也回得来 |

嵌不嵌得成由对方响应头决定（前端绕不过）。实测 `curl -D`：

```
HTTP/1.1 200 OK · Server: nginx/1.27.5 · Content-Type: text/html
（无 X-Frame-Options，无 CSP frame-ancestors）
```

可被嵌套。

### 52.2 一个决定：原有「画布全屏放大」不撤

「全屏」这个按钮原本的职责是**放大站内画布**（v21 起）：DAG 是 viewBox 等比缩放，
中栏 668px 时 7 节点流程只放大到 0.64 倍、节点文字被压到 ~7px，铺满后读得清。
这条能力有 13 条断言正断着。

直接改成「全屏 = 进外部系统」等于把这个能力连根拔掉。所以做成**两个视图共存**：

```
点「外部编排」→ #orch 铺满视口 → .orchext 接管、站内画布收起
                    └─ bar 上「返回站内画布」→ 同一全屏壳里换回画布（仍放大）
                再点「收起」/ Esc / 跳页 → 整体退出
```

`setOrchExt(on)` 是唯一的状态切换点，与 `toggleOrchFull(force)` 正交：
全屏管**尺寸**，外部视图管**内容**。退出时两边一起复位，否则下次进编排页是块白板。

### 52.3 复用 v58 的 iframe 模式

照知识库那三页的同一套写法，不另立一套：

- `ORCH_EXT_URL` 是地址**唯一来源**，HTML 里不写死（换服务器只改这一处）
- iframe 的 `src` 由 `mountOrchExt()` 运行时 `setAttribute` → **产物里没有 src 属性**，
  只能靠运行时探针 `window.__orchExt()` 断
- `load` 在被拒/超时时不触发 → `setTimeout(8000)` 兜底判失败，
  失败态给**真实可点**的「重新加载 / 新标签打开 / 返回站内画布」
- **刻意不把「iframe 加载成功」写进断言**：能否达取决于跑回归的机器有没有接那个网络，
  那是环境不是缺陷，写进去等于埋一颗「换台机器就红」的雷

### 52.4 两个 CSS 坑

**① `.orch__b[hidden]` 兜底**。`.orch__b` 是 `display:grid`，UA 的 `[hidden]{display:none}`
压不住类选择器 —— 缺这条就等于没收画布，外部系统与画布会叠在一起。
`.orchext[hidden]` / `.orchext__ph[hidden]` / `.orchextfail[hidden]` 同理各自声明。

**② flex 子项的 `min-height:auto`**。`.orch.is-full .orchext` 必须显式
`flex:1; min-height:0`，否则 iframe 内容高会把容器撑破、全屏壳里出现双滚动条。

### 52.5 断言：原 13 条一条不减，另加 11 条

原 13 条里**量的时机必须改**：全屏后 `.orch__b` 被收起来了，此时量画布宽度必然是 0。
所以改成「点全屏 → 量外部系统接管 → 点「返回站内画布」→ 再量画布是否变宽」。
`grew` / `vCenter` 两条断言的**判据一个字没改**，只是挪到了正确的时机。

新增 11 条分三组：**未进入**（不预挂、默认站内）/ **全屏接管**（挂上正确地址、
接管画布、iframe 铺满、失败退路真实可点）/ **退出复位**（Esc 后、跳页后都让位画布）。

截图也拆成两张：`23-orch-ext.png`（外部系统）与 `23b-orch-full.png`（切回画布的全屏态）。
只拍一张就有一半断不出来 —— 两张都要登记 `SHOT_PAGE`。

### 52.6 还原点

`_backup-v1/v60-orchext/`。
