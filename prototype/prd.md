## 1. 产品概述

### 1.1 产品定位

面向中医院 / 研究机构组学科研场景的一站式数据挖掘系统，覆盖**数据汇集 → 流程模板 → 参数配置 → 任务运行 → 查看分析结果**的完整分析线，以及项目、样本、文件、知识库、项目组等管理域。

### 1.2 目标用户与角色

系统采用**三档角色、一套权限模型**，全站唯一身份入口为顶栏用户切换器：

| 角色 | 适用人 | 权限 | 界面差异 |
|---|---|---|---|
| 超级管理员 | 信息科 / 样本库负责人 | 所有权限（含平台级配置） | 完整视图 |
| 普通管理员 | 主管 / 知识库管理员 / 项目负责人 | 增删改查 / 审批 | 完整视图（无平台级配置） |
| 普通用户 | 实验人员 / 科研 PI | 查看 / 新增 | 工程细节不可见 |

- 权限判定统一走三个函数：`canManage()`（超级 / 普通管理员）、`canConfig()`（仅超级管理员）、`isBasic()`（普通用户）。
- **权限不足不隐藏控件，只禁用并说明原因**——控件可见性不随身份抖动，符合医疗场景合规与可审计要求。
- 角色差异在工程细节层表达：普通用户视角下参数面板折叠为「推荐配置」，镜像版本 / jobId 等工程列隐藏（`body[data-role="user"] .eng-only`）。

### 1.3 设计原则

1. **无演示措辞**：界面上不出现「演示 / 模拟」等脚手架字样，全站可检索验证为 0 处。
2. **告警状态驱动**：没有「触发某异常」的按钮；看到什么提示取决于当前上下文状态（缺失率、样本数、队列位次等）。
3. **无假交互**：画成按钮就必须有处理器，说了能拖就必须能拖；未实现功能显式标注。
4. **无障碍 WCAG 2.1 AA**：每张图表提供「查看数据表」替代视图；状态不靠颜色单一传达；正文对比度 ≥ 4.5:1。

## 2. 总体架构

### 2.1 信息架构（17 页 / 左栏 4 组 10 项）

| 左栏分组 | 页面 | 是否在菜单 |
|---|---|---|
| 工作台 | 工作台（p01） | 是 |
| 数据资产 | 样本档案（gene）、文件管理（files） | 是 |
| 项目空间 | 项目管理（proj） | 是 |
| 智能分析 | 数据汇集（p02）、流程模板（p04）、参数配置（p05）、任务运行（p06）、查看分析结果（p07） | **否（整组撤出菜单）** |
| 知识赋能 | 医学知识库（kbmed）、自有知识库（kbown）、知识图谱（kbgraph） | 是 |
| 系统管理 | 运行日志（log）、项目组管理（projgroup）、示例数据集（pubds） | 是 |

菜单外共 7 页：**项目概况**（projdetail，从项目列表钻取）、**样本管理**（sample，另安排入口），以及智能分析整组 5 页（p02 / p04 / p05 / p06 / p07）。

**设计说明**：智能分析组不上菜单的理由——它是「一次性把数据跑到结论」的线，入口应是「新建项目 › 智能分析」；菜单与分析入口并存会让用户在「先建项目还是先跑分析」上卡一次。页面、跳转、面包屑组名段全部保留。

### 2.2 两条产品主线

**主线一：一键全流程向导（建项目路线，6 步）**

```
项目信息 → 数据文件 → 分组与比较方案 → 流程模版 → 参数配置 → 创建完成
```

- 末段「任务运行」不进向导：建完才跑。
- 提交后回项目列表并置顶，回执含流程模版与参数配置信息。

**主线二：智能分析工作台线（不建项目，5 步）**

```
数据汇集 → 流程模板 → 参数配置 → 任务运行 → 查看分析结果
```

- 「任务运行 → 查看分析结果」之间有**状态闸**：任务未结束时「查看结果」按钮拦截点击，防止人站在结果页看上一批数据的结果；页脚「下一步」入口不受任务状态影响。
- 第 5 步结果与项目详情「结果全景」为**同一份内容、两个入口**，六个视图与三张数据表口径完全一致。

## 3. 全局通用功能与交互规范

### 3.1 导航与返回

- **返回只走面包屑**：全站没有「← 返回」条；顶部面包屑每一段都可点，上一级与横向菜单都从这里回去。钻进项目后左栏整体换为该项目的专属菜单，出层唯一路是面包屑。
- 左栏深色外壳（L 形），同时回答「我在哪」「我能去哪」；菜单内页面在筛选时**不自动收起左栏**。

### 3.2 下载 / 导出（统一链路）

全站 14 条下载 / 导出入口走同一条链路：**点击 → 确认弹窗 → 浏览器真实落地文件**。

- 确认框写清四件事：文件名、格式与行数、体积、来源。
- 产出类型：TSV / CSV 表格、SVG 图、JSON 溯源报告、ZIP 结果包（13 张 SVG + 19 张 TSV，标准解压器可开）。
- **动作列不导**：操作列是界面按钮，序列化时整列丢弃。
- 内置示例条目（无实体文件）点下载直接说明，不弹确认框。

### 3.3 弹窗体系

- 全局复用一个弹窗壳：新建项目向导、知识采集、下载确认、完善项目信息等共用；底栏按钮随内容注入。
- 同一时刻只有一个活动弹窗；**Esc 逐层退出**：先关最上层浮层，再按一次才收抽屉，不连关多层。
- 表单类弹窗缺必填项时拦截提交：toast 指明缺哪项、焦点回落到该字段、控件标错误态。

### 3.4 必填字段规范

必填字段统一用提醒色星号 `*` 标识：字段名后挂星号、表单尾部一行图例说明、控件挂 `aria-required="true"`。标了必填就要真的拦得住空值。

### 3.5 任务中心

顶栏铃铛徽标数字与弹层里的队列行是**同一份状态**：排队 / 运行中数量变化同时反映在两处，点某条队列行可跳到对应任务。

### 3.6 表格规范

表头与单元格内容统一居中对齐（数字与日期列也不例外）；样本列表选中项永远可见（自动翻页到选中行所在页）。

### 3.7 告警与引导式修复

四类告警均**状态驱动**，统一走三要素：**说明原因 → 给可执行动作 → 允许继续**。

| 告警 | 触发状态（演示阈值，待院方确认） | 引导动作 |
|---|---|---|
| 格式不支持 | 上传文件扩展名不在白名单 | 自动转换 / 下载格式模板 / 重新上传 |
| 缺失率过高 | 缺失率 > 20% | 中位数填充 / KNN 填充 / 剔除样本 / 剔除特征（附前后对比预览） |
| 样本量不足 | 样本数 < 30 | 继续但标注低置信 / 合并其他队列 / 改用非参数方法 |
| 算力排队中 | 任务提交后进入排队 | 排队态只显示「请等待」（v63 起不再弹出算力排队引导） |

三个阈值集中配置（缺失率 20%、最小样本 30、队列位次 5），改一处全站生效。

## 4. 功能详述

### 4.1 工作台（p01）

| 功能 | 说明 |
|---|---|
| 智能体问答卡 | 首页问答卡是智能体会话的**唯一宿主**；快捷提问与输入框共用同一份会话日志 |
| 写操作确认闸门 | 涉及写操作（如「跑 RNA-seq 流程」）时，智能体先给确认框：确认才写入运行历史并把对应流程翻成「运行中」，取消不落任何记录 |
| 卡片全屏 | 右上角全屏只是放大当前卡片，不产生第二份会话；全屏态遮蔽标注浮层 |
| 队列概览 | 展示算力队列当前状态 |
| 运行历史抽屉 | 与编排区流程状态同源：确认执行后新记录插到最前，对应流程同时翻成「运行中」 |

### 4.2 样本档案（gene，数据资产组）

| 功能 | 说明 |
|---|---|
| 样本列表 | 队列 75 例（基因组 / 转录组各覆盖 75，蛋白组 71，三组学共同样本 71）；列含数据来源（系统 / 自创建 / 示例）、质控结论、组学覆盖三字标（基/转/蛋）、资料数；不再展示「性别 / 年龄」列 |
| 搜索与筛选 | 样本 ID 搜索框与疾病 / 质控 / 组学 / 状态四个下拉同排，共用同一份状态；点击列头排序、每页 15 条分页 |
| 特定样本条 | 选中一行即出现该样本的指标 / 信息 / 血缘 / 跨组学 / 资料；顶部四格按血缘四层配色 |
| 样本信息 | 27 个字段四路现算合成（顶层字段 + 血缘派生 + 跨组学派生 + 元数据），不是静态表 |
| 血缘谱系 | 横向「层级 = 列」泳道图 ⇄ 上下结构双视图切换；边数恒等于节点数 − 1 |
| 详情抽屉 | 样本详情为五块一体的右侧滑出抽屉（概要 / 分组 / 数据 / 文献 / 操作），**无遮罩** |
| 资料归档 | 从本机选真实文件归档；内置示例条目与真实归档件下载行为分开处理 |

**数据口径**：4 例蛋白组缺失样本（S004 / S021 / S052 / S063）同时是质控「不合格」的 4 例——缺失原因与质控结论是同一件事的两种说法，改一处必须核另一处。

### 4.3 文件管理（files，数据资产组）

| 功能 | 说明 |
|---|---|
| 三档可见范围 | **个人文件**（仅本人）/ **团队文件**（所选项目组成员）/ **系统文件**（全员只读）；档位切换同时决定上传落点与列表范围 |
| 团队上传 | 必选所属项目组才能提交，文件随之对该组成员可见 |
| 上传限制 | 上传侧不限文件格式——格式异常在分析侧（数据汇集）拦截，不在上传时挡人；上传方式统一为拖拽 / 选择文件，不再区分 web / FTP |
| 文件树 | 个人 / 团队 / 系统三档文件树 + 搜索；文件树结构单一来源渲染 |
| **系统文件写权限** | 系统文件是**平台公共参考数据**，写权限 `fmCanWrite()` = `canConfig()`（仅超级管理员）；读权限三档全开。只读身份下上传卡不隐藏，换成警示说明；行内删改用禁用态图标 |

### 4.4 项目管理（proj，项目空间组）

| 功能 | 说明 |
|---|---|
| 项目列表 | 8 列：项目编号 / 项目名称 / 负责人 / 样本 / 分析步骤 / 项目状态 / 最近更新 / 操作；含「项目状态」列（成功 / 分析中 / 失败），状态由最新一次运行决定、与任务运行状态联动。已去掉「可见范围」列与项目名旁的「当前」标签 |
| 新建分流 | 点「新建项目」先出**路线分流屏**：一键全流程分析（进 6 步向导）/ 智能分析（进 5 步工作台线）；分流屏不创建任何项目 |
| 6 步向导 | 项目信息（所属项目组下拉）→ 数据文件（两栏文件选择器，**无「测序类型」选项，勾选文件后可直接下一步**）→ 分组与比较方案 → 流程模版（列表 + 明细，必选一条）→ 参数配置（12 控件 + 实时摘要）→ 创建完成回执 |
| 钻取详情 | 点项目进独立「项目概况」页（非弹窗）；返回只走面包屑 |

### 4.5 项目概况（projdetail，菜单外）

| 功能 | 说明 |
|---|---|
| 七个页签 | 概况 / 样本 / 数据集 / 参数 / 参考 / 流程 / 运行；各页签计数来自项目实时状态现算 |
| 数据集页签 | **数据集是分析项目的产物**，无独立一级页面，只住在这里；跨组学「查看数据」直达该页签明细 |
| 页头操作条 | 项目状态徽章 + 分享此项目 + **查看项目结果全景**（人已站在结果全景那格时按钮自动隐藏） |
| 项目专属左栏 | 钻进项目后全局菜单整条让位，换成该项目的菜单：项目详情｜分析执行｜分析结果 |
| 结果全景模块 | 六个视图 + 三张数据表；与分析线第 5 步共享同一份内容，同一时刻只挂载一处 |
| 项目信息字段 | 键值 8 行：项目编号 / 项目名称 / 负责人 / 参考基因组 / 样本数量 / 创建时间 / 最近更新 / 项目状态（已去掉项目类别、物种、可见范围）；项目描述下不再挂标签 |
| 分享 | 前端生成分享链接与有效期短链（正式实现为二维码 + 访问审计） |

#### 第 3 步：参数配置（p05）

| 功能 | 说明 |
|---|---|

| 阈值依据 | 「阈值依据」卡承载三项统计口径（缺失率 20% / 最小样本 30 / 队列位次 5），标注待院方确认 |

#### 第 4 步：任务运行（p06）

| 功能 | 说明 |
|---|---|
| 本次分析信息条 | 走过弹窗后出现，复述弹窗全部七项供运行期间核对 |
| 横向流水线 | 节点按阶段定义依次排列（wait / run / done 三态驱动）；运行中节点带百分比与剩余时间 |
| 排队态 | 只显示「排队中 · 请等待」，不展示算力队列、队列位次、预计耗时与「系统检测到的问题」模块；再点「开始执行」即开跑 |
| 状态闸 | 「查看结果」按钮在任务未结束时点击只提示等待不跳页；结束后落点在本线第 5 步 |
| 其他 | 运行命令卡、对齐明细卡（可导出 TSV）、运行日志导出 |

#### 第 5 步：查看分析结果（p07）

| 功能 | 说明 |
|---|---|
| 六个视图 | 基因变异 / 差异表达 / 功能富集 / 蛋白组 / 代谢组 / 跨组学对齐 |
| 数据表 | 三张数据表随视图切换；每张图都有「查看数据表」替代视图 |
| 与项目详情同源 | 与项目概况「结果全景」是同一份结果模板，同一时刻只挂载一处 |
| 图表设置 | 每张图右上角「⚙ 设置」打开右侧面板，可实时调整宽高、背景色、网格线、线条宽度、图例、上调 / 下调 / 未显著配色、主标题文字与字号颜色；可一键恢复默认 |
| 表格下载 | 每张图的数据表旁「下载表格」，走统一确认框后导出 TSV；六个结果表的「导出」按钮保留 |

### 4.7 样本管理（sample，菜单外）

- 列表与计数**跟随当前项目**：页头显示当前选中项目，列表、计数与筛选都限定在该项目范围内。
- 候选样本已支持定位回显：筛选重置后自动回到定位。

### 4.8 知识赋能（3 页）

三页各自**页内挂载外部系统**：页头 `.seg` 切「外部系统 / 站内版本」，默认外部系统。外部系统地址唯一来源 `KB_EXT_BASE`（医学 /ke、自有 /kb、图谱 /kg），iframe 运行时挂载 src，加载失败（被拒/超时）以 setTimeout 兜底提示。

#### 医学知识库（kbmed）

| 功能 | 说明 |
|---|---|
| 四个知识域 | 临床诊疗（主域）/ 生物样本 / 多组学 / 权威文献，共 58 个词条 |
| 三种模式 | 检索 / 浏览 / 管理同源，读同一份数据 |
| 生命周期 | 词条状态机 draft → review → pub → arch；仅**已发布**词条对全员可见 |
| 知识采集弹窗 | 两段式：第一屏选知识域；第二屏选**手动填写**或**批量上传**（互斥），四域差异字段模块由域配置驱动 |

#### 自有知识库（kbown）

- 上传自有文献 / 资料，要点解析后入库（原型内要点为前端生成；正式实现为向量化原文片段、页码定位与出处链接）。

#### 知识图谱（kbgraph）

- 以样本为核心节点串起三类证据：疾病与用药、分子证据、通路与文献；点节点右侧给出该实体的证据条数与可追溯来源（原型内为圈图占位）。

### 4.9 系统管理（3 页）

#### 运行日志（log）

- **全员视图**与**个人视图**两套口径。
- 管理员角色下额外显示镜像版本与 jobId 列（普通用户隐藏）。
- 支持按日期范围与动作组筛选；日志可导出 `.log` 文件。

#### 项目组管理（projgroup）

| 功能 | 说明 |
|---|---|
| 三档权限 | 治理（增删改查 / 审批）走 `canManage()`；页头身份为只读徽标 |
| 删除保护 | 只有「已驳回」的项目组可删除；删除按钮选中行后点亮，点击先出确认弹窗 |
| 全站唯一名单 | 项目组名单是**全站唯一来源**：新建项目「所属项目组」下拉与文件管理团队上传读同一份，且只有「已通过且启用」的组会进入下拉 |

#### 示例数据集（pubds）

- 9 条内置数据集（公开 6 条 + 院内队列 3 条）逐条控制**显示 / 简介 / 封面**。
- **设置侧与展示侧读同一份数据**：这里隐藏的条目在数据汇集的数据源选择处同步不可见。
- 「恢复默认」回到出厂快照（不是清空全部设置）。
- 本页写权限 `canConfig()`（仅超级管理员）。

## 5. 关键业务规则

| # | 规则 | 说明 |
|---|---|---|
| 1 | 样本 ID 对齐（P0） | 跨组学关联的唯一键是**样本 ID**，不是项目、文件名或批次；按共同样本口径对齐；ID 映射（如 S068A → S068）必须显式可审计，不静默归并 |
| 2 | 项目是隔离边界 | 项目是权限与数据的双重边界；所有列表查询都带项目上下文 |
| 3 | 数据集是分析项目的产物 | 没有独立一级页面，只出现在项目概况的 dataset 页签 |
| 4 | 流程模板决定主流程 | 主流程节点、参数默认值、结果模块清单均由模板派生 |
| 5 | 信息先落、再开跑 | 「运行分析」先补全项目信息并确认，任务才提交 |
| 6 | 任务未结束不进结果 | 「查看结果」状态闸拦截，防止看上一批数据的结果 |
| 7 | 知识库状态机 | draft → review → pub → arch；仅已发布词条全员可见 |
| 8 | 新建即设为当前 | 新建项目后排最前并自动成为当前项目 |
| 9 | 权限一套到底 | 权限只走 `canManage()` / `canConfig()` / `isBasic()`；权限不足禁用而非隐藏，事件委托里第二道同样判断 |

## 7. 接口契约（预留真后端）

界面只依赖以下 7 个端点，原型阶段由前端 mock 实现（内置数据集 + 定时器模拟），接真后端时替换实现层即可，界面代码零改动。

| 端点 | 请求关键字段 | 响应关键字段 |
|---|---|---|
| POST /api/v1/omics/upload | file, data_type | file_id, detected_format, sample_count, quality_report |
| POST /api/v1/omics/align | file_ids[], id_field | aligned_samples, unmatched_samples, overlap_matrix |
| GET /api/v1/omics/pipelines | data_type | pipelines[{id, name, tools[], default_params}] |
| POST /api/v1/analysis | pipeline_id, params, role | task_id, queue_position, est_duration_sec |
| GET /api/v1/tasks/{task_id} | — | status, progress, logs[], resource_usage |
| GET /api/v1/analysis/{task_id}/result | — | metrics, charts, omics_result, interpretation |
| GET /api/v1/trace/{task_id} | — | data_version, params_snapshot, intermediates |

**前端模拟范围**：数据上传、知识库解析、检索、图谱（圈图占位）、项目分享链接、工具运行（定时器推进进度）。
**已按真实行为实现**：真实文件选择、真实下载、扩展名校验、拖拽落文件、告警状态驱动、跨页返回栈。
