# 天中医 · 踩坑速查（详版）

> `MEMORY.md` §5 只留最高频的几条，全文在这里。每条都是真踩过的，改之前先读。

## 一、浮层与层叠

1. **z 表**：画布 58 < 遮罩 60 < 抽屉 61 < 二级抽屉 62 < 弹窗 70 < 智能体浮窗 89 < 浮球 90。
   编排区全屏与主页问答卡全屏都取 58（高于顶栏 40，低于遮罩/抽屉/弹窗）。
2. **遮罩在 DOM 里排在弹窗体之前**。`q('#modal [data-close="modal"]')` 命中的是 `.back`（遮罩），
   它的中心被 `.modal__b` 盖着 → 命中测试必然返 false。要点那个 ✕ 得写
   `q('#modal .iconbtn[data-close="modal"]')`。（两种点法走的是同一个 `[data-close="modal"]` 分支。）
3. **模态/抽屉/浮窗断言一律「中心点能被自己接住」**：`elementFromPoint` 拿到的是不是它自己。
   遮挡断言只需几何覆盖，不要求可命中 —— 两者不是一回事。
4. **抽屉第三态**：`!hidden` 但 `is-open` 已摘 → 只有 `elementFromPoint` 会返 null。
   往抽屉里搬内容会静默放宽检查口径，搬之前先想清楚这条还守不守得住。
5. **浮球压按钮**：`fixed right/bottom 22px`、z 90 的浮球会压在全屏层底栏的发送键上
   （v31/v32 抓过两次）。全屏时用 `body.is-agentfull` / `body.is-wbfull` 把它整颗 `display:none`。
6. **全屏层 z 若高于弹窗**（智能体浮窗 89），`showModal()` 里必须先把它缩回，否则弹窗开在它背后点不到。

## 二、断言与探针

7. **不碰运气**：段首显式起点、切页段回位；数字一切现算，写死计数会随数据集体变红。
   非契约数字换成不变式（如「边数 = 节点数 − 1」）。
8. **调试钩子写成「不传参 = 纯读」**：`function (v) { if (v !== undefined) set(v); ...read }`。
   写成 `function (v) { set(v); ... }` 的话，断言里一句 `hook()` 就等于**先切换再读**，
   基准 rect 会直接量成目标态（v38 踩过：基准量成了全屏态，`home` 变成了 1396×956）。
   反过来，断言里用 `hook(true)` 强制设成想要的状态再读回，会把「点击坏了」伪装成通过。
9. **探针键挂错层级只报 `<缺失>`**：`R.wbFull.on.hit` 写成 `R.wbFull.hit`，断言只显示 `<缺失>`，
   不告诉你挂错层。看到 `<缺失>` 先回去看赋值那一行的层级。
10. **伪元素不是 DOM**：取 `getComputedStyle(el, '::before')`。
11. **`FAI[name].p` 已是完整 path 标记**，再包一层会截断成文字；嵌套 `<svg>` 要带 x/y/w/h。
12. **浮点比较用容差**；写死的 md5/尺寸比较要留容差或改成区间。

## 三、截图

13. 截图之间会残留浮层与选中态；命中测试前先 `scrollIntoView`。
14. **两张截图 md5 相同 = setup 没执行**（或确实什么都没变）。
15. **setup 里选择器写错只静默落空** —— 那一版图其实是「没改过」的状态，名字却叫改动后的名字。
    `SHOT_PAGE` 只管「页对不对」，管不了「状态对不对」。
16. 新增截图必须在 `SHOT_PAGE` 登记期望页，否则「每张截图都停在目标页」直接红。
17. **看截图别只信缩略图**：降采样会造出假的「贯穿整宽的细线」。怀疑时用
    `page.screenshot({ clip })` 拍 1:1 局部，或直接量元素几何（v38 就这么排除掉的）。

## 四、结构与渲染

18. **搬容器先 grep 该 id 的全部引用**：renderFM 的守卫漏改过一处，导致整页渲染空（v33）。
19. **DRIVE 段的辅助函数必须前置**（TDZ）；`display:none` 的 `.click()` 仍会派发事件。
20. **DRIVE 段 `q` 是 `querySelector`（单个元素）**，`q(...)[0]` 会拿到 undefined 并把整段驱动打断
    （`Z_ERROR: Cannot read properties of undefined (reading 'click')`），后续 R 键全缺，
    Python 侧连锁报 `TypeError`。要数组用 `qa(...)`。
21. **verify 的 needs 区是纯 Python**（无 await）；截图 setup 串是 JS，**分号不能省**。
22. 页面流里的元素做「就地全屏」= 脱流，会带走它占的那一格高度（侧栏塌成 0、整页往上跳）→
    先用占位（父容器 `min-height`）把原格占住，并用「下方元素的 top 不变」守住「缩回的是原位置」。

## 五、多套左栏 / 分层导航（v41）

25. **左栏可能不止一套**（全局菜单 vs 项目层菜单）。`renderNavOn()` 只改高亮、**不重建 DOM** ——
    换上下文时必须显式重画，否则「出了层左栏还挂着上一个上下文的菜单」，看起来像串页。
    做法：一个 `NAV_MODE` 标记（此刻渲染的是哪一套），`renderNavOn()` 先比标记再决定重画。
26. **左栏换了套 ⇒ harness 的导航入口要一起演进**：`goPage(p)` 查 `[data-go]`，在项目层里返回 `null` →
    `null.click()` **打断整段驱动脚本**，其后探针一条不跑。修法照用户的真实走法：
    先点面包屑退回上一层、再点左栏那条（`window.__navFallback` 记次数）。
    **v50 补一刀**：`window.__go(p)` 是 `if (b) b.click()` —— 找不到按钮时**不报错、静默什么都不做**。
    用在截图 setup 里就是「图拍在上一页、断言全绿」。**菜单外的页面一律用 `window.__goRaw`**。
27. **钻取层的左栏里没有全局菜单 ⇒ 出层唯一路是面包屑**（v17 那条规矩在这一层才真落地）。
    断言要断「出层之后全局菜单回来了（14 条）」而不只是「页对了」。
28. **分栏之后，断言的分母跟着「当前渲染了哪一栏」走**：`panels` 7→5；`flRows`/`lgRows` 要搬到执行栏量；
    空态计数按栏分家。在错的栏上量只会得 0 —— 那不是「没数据」，是**量错栏**。
29. **上下文相关的下载条目**（如「导出本步清单」只在模块页上有内容）别混进「每条都必有内容」的一拨，
    否则正常行为被误判成坏条目；单独在它自己的上下文里取一次。
30. **页签条与横向流程条共用一个位置时必须互斥**：同时出现是同屏两条导航，同时消失是没有任何方向感。
    切换实现要「跨栏整批重画」，只切 `.is-on` 会切出「页签条在、面板全灰」的空白屏。
31. **要改的字符串如果同时被当「匹配 key」用，动手前先 grep 全仓扫数据**。`pdtHit` 这类
    **词元对齐**拿模块名去匹配数据集名 / 日志说明 —— 把「可视化报告」改成「结果全景」时，
    若新名字已被某条数据集名或日志说明包含（`pdtTokens` 不切中文串，4 字是一个整词元，
    必须整串出现才算命中），那个模块会**从空态凭空多出一条记录**：界面看着「改对了」，
    其实是误命中。（本轮提前 grep「全景」确认数据集名 / 日志说明都没有，才敢改。）
    同理，**同名的「参考系统实测记录」不能顺手一起改** —— 那是实测事实，不是本系统的文案
    （本轮 `原型设计说明.md` §33.1 参考系统那行就保持「可视化报告」不动）。
    改名类需求的收尾三件事：代码（唯一来源一处）+ 断言里的期望值 + 文档里的规则；
    改完必看**截图 md5 有没有变**（没变说明那片 UI 根本没动）。
32. **搬静态内容进 `<template>`：先找出「谁在启动时照顾它」**。模板 content 不在文档树 ——
    `init()` 里那些全站遍历（`fillTables()` 填表体 / `.chartbox` 渲染图表 / `setView()` 切视图）
    都会漏掉它，挂载后必须补做。漏 `fillTables()` 的表象最阴：表里没数据看着只是「没填」，
    而 `dlFromTable` 见 `rows < 2` 会返回 `null` → 导出按钮**点了没反应**。
    好消息是 `fillTables()` 用 `innerHTML` 覆盖写、幂等，反复进出这一页不会把行叠起来。
    另外：**能原地降级就别搬 DOM** —— `<template>` 的内容不渲染也不占位，
    所以把 `<section class="page">` 就地改写成 `<template>` 即可，一个字节都不用挪。
33. **撤/改一个钩子前先问「谁在借它」**：
    · 撤操作条那颗 `[data-proj-golog]` 时，`pdtRunPanel` 里还有一颗同名的才是那条分支真正的用户
      —— 分支不能跟着删（差点把别人的路一起铲了）。
    · `#btnResult` 的「任务还没结束」禁用闸门写在 `[data-go]` 分支里；按钮改挂 `data-pano` 之后
      就不再经过那条分支，闸门必须一起搬过去，否则禁用态形同虚设、点了直接跳走。
34. **探针的兜底值不能拼进选择器**。`qa('#' + lid + ' .snav__n')` 里 `lid` 取不到时给的是 `'(none)'`，
    于是 `querySelectorAll('#(none) .snav__n')` → **非法选择器抛错 → 打断整段 DRIVE**
    （第四次了：v39 / v40 / v41 / v42）。正确形态是 `n: lid ? qa(...).length : -1` ——
    取不到就报一个不可能通过的值，让断言自己红，而不是把整段驱动炸掉。
    这次触发它的场景也值得记：借某个页面/模块做 A 测试之后**忘了把页面状态换回来**，
    后面的探针（`R.ia` 量全局左栏）就落在一套完全不同的 DOM 上。
    凡是「借某个上下文做测试」，测完问一句「页面状态还回得去吗」。
35. **撤一个入口 ≠ 撤一项能力**（v43 撤项目概况页头的「查看项目结果全景」）：
    · 验证段不能跟着入口一起消失 —— `R.projPano` 原先是「点页头那颗 → 查落在结果全景模块」，
      按钮撤了要**换驱动路**（改点左栏末一格 `[data-pdmod="N-1"]`），检查项一条不减。
    · 必补一条**文案残影**断言：`#projActs .btn` 的文字里不许再出现「全景」。
      撤按钮最常留下的就是文案（按钮删了、label 还在某处拼）。
    · **删钩子分支时要挑着留函数**：删 `[data-proj-pano]` 分支 ≠ 删它调用的 `setCurProj()`
      —— 卡片点击、启动初始化另外两条路还在用它。
    · 入口的**显隐方式**也是断言对象：从「有运行记录才显示」改成「固定一处」之后，
      原来那句「无记录不给入口」的断言要改写成「对任何项目恒 0」，否则它会在空项目上继续假绿。
    · **v46 补第 5 条**：撤除时「验证脚本的引用」要**按探针名逐个 grep、一次清完**。
      v46 删掉 `window.__geneClose` / `window.__sampTab` 后，**截图 setup 里各 16 处**引用
      （共 32 处）没清 → 抛 `TypeError` **打断整段 setup**，其后所有截图都拍在当前页。
      这是同一个坑的**第五次**（v39 `__projClose` 16 处 → v40 `[data-kb2add-ok]` → v41 `goPage()`
      → v42 `#(none)` → v46 `__geneClose`/`__sampTab` 32 处）。
      清法：写一次性脚本按行处理「整行单句」与「同行混排」两种形态，并在脚本末尾加
      `assert '__geneClose' not in src` 之类的**终态断言**，别靠肉眼数。
36. **探针字段名与既有探针键撞名 → 静默覆盖 → 读到「语法正确、语义无关」的真值**（v44）：

    **比 `<缺失>` 毒**：`_Miss` 一眼就看出来，`'1'` 是个真数字，看着像「确实有 1 个」。

37. **把一个元素的显隐从「渲不渲染」改成「常驻 + `hidden`」时，有三处必须同时改**（v45）：
    · **CSS**：`.btn` 是 `inline-flex`，UA 的 `[hidden]{display:none}` 被类选择器压掉，
      必须逐容器声明。文件里早有一条 `.phead__side .btn[hidden]`，但 `#projActs` 是
      `.pd__act`、**不在** `.phead__side` 里 —— 照抄那条的适用范围正好漏掉它。
      漏了的表现：`b.hidden = true` 设了、按钮照样躺着，看着像「代码没生效」。
    · **探针量法**：`qa('#projActs [data-x]').length` 从「在不在」变成**恒为 1**
      （节点一直在）。改读 `hidden` **且** `getBoundingClientRect().width > 0` ——
      只看 `hidden` 的话，漏了上面那条 CSS 时断言照样绿。
    · **生成后补一次**：重画出来的节点是**新节点**、默认没有 `hidden`。
      `renderProjHead()` 末尾补 `markProjPano()`，否则会先露一下再被隐掉。
    另一条通用提醒：**条件显隐必须配一条反向断言**（「换到别的格，它自己回来」）。
    只断「在该隐的时候隐了」，把条件写成「进过一次就永久不显示」也照样绿 ——
    而那正是这一版要避免的过度撤销（v43 已经犯过一次同类的错）。

## 六、环境

23. Chrome 启动须 `dangerouslyDisableSandbox`，并带 `--use-mock-keychain --password-store=basic`。
24. 钥匙串 / 系统日志的坑见 `REF-工具链.md`「macOS 环境坑」——别点「还原为默认」；
    zsh 里 `log` 是内建命令，查系统日志用 `/usr/bin/log`。
25. **本机 `grep` 不支持 GNU 的 `\|` 分支**（`grep -n "A\|B" file` 静默返回空、exit 0），
    也不支持 `\b`。**多模式搜索一律用内置 Grep 工具（ripgrep），不要用 Bash 的 `grep`。**
    v46 因此在 Bash 里白查两轮，一度误判成「中文模式匹配失败」（同一条命令在有命中的确有结果，
    只是 Pattern 里带了 `\|` 的那两处返回空 —— 空结果和「真的没有」长得一模一样）。

## 七、撤销功能 / 入口改道（v50）

38. **「撤功能时顺手把探针删掉」= 这个功能从此再也守不住。**
    v50 撤左栏数量徽标时，`navSubNums`（「智能分析二级不再带步骤号」）的宿主 DOM
    随着「整组不上菜单」**已经不存在** —— 这条探针留着只会永远返回 `-1`、常红且无法修。
    正确姿势不是删掉它，而是**换个位置继续守**：它守的事被 `navBadges` 接过，
    从「盯一个组」升级成「盯**整条左栏**」，比原来更严。
    **撤一个东西要问两句**：哪些**引用**要跟着删（不删会抛错/静默落空）；
    哪些**守卫**要跟着搬家（不搬就悄悄失守、或变成一条永远红的噪声）。

39. **同一条事实有两个消费方时，撤的往往只是其中一个。**
    v50 撤徽标：数量的第二个消费方是**页面内的文字**（项目列表头「共 N 个项目」、
    文件管理计数、项目组页「可选 N 个」——后者还是新建项目下拉的条数来源）。
    它们只是**碰巧同源**，撤左栏那一个时一个都不该动。
    断言也要跟着改口径：从「数字是多少」改成「**一个都没有**」（`navBadges == []`），
    而不是把期望值从 13 改成 0（那样下次加回来也看不出来）。
    ※ 但**类名 `.snav__n` 不能撤** —— 项目层左栏的状态记号（`✓ ! ·`）还在用它。

40. **「页数 − 菜单项数 = 常数」这类等式，只在「哪些页不上菜单」不变时成立。**
    v47 定的不变式「页数 = 菜单项数 + 2」在 v50 整条作废：页数还是 16，
    菜单项却从 14 掉到 10，差值变成 6。
    换成**不含任何常数的分类不变式**：每个页面要么在菜单里、要么落进 `offMenu` 这批
    （两者并集 = 全部页面）。**页数仍可单独断**（它是事实，不是推导结果），
    但不要再和菜单项数做加减 —— 写死一个数会「下次要么漏改一处，要么把魔数当结论」，
    而写一条会随功能作废的等式更坏（它会以「红的」形式误导下一个人）。

41. **菜单外的页面，三种取法三种坏法 —— 而且有一种完全不报错。**

    | 取法 | 坏法 | 改成 |
    |---|---|---|
    | `q('[data-go="pXX"]').click()` | 选择器 `null` → `null.click()` **抛错打断整段 DRIVE**（其后几百条读数全 `<缺失>`） | `window.__goRaw(pXX)` |
    | `goPage('pXX').click()` | 同上（`goPage` 找不到就返回 `null`） | 先判空，没有就走 `__goRaw` |
    | `window.__go('pXX')`（截图 setup） | **不报错**：内部 `if (b) b.click()`，静默什么都不做 → **截图拍在上一页** | `window.__goRaw(pXX)` |

    第三种最阴（断言全绿、只有图错），**唯一拦得住它的是 `SHOT_PAGE` 那张「每张图该拍哪一页」的表**。
    v50 它确实拦下三张该拍 p04 却拍到别页的图。
    ※ 但**不要**去断「哪几页必须走直达」：`goPage()` 在左栏里找不到时会兜到**任意** `[data-go]` 按钮
    （数据汇集 / 流程模板这些页面里本来就到处是「下一步」），于是菜单外的四页照样是 `'nav'`。
    那不是漏网，是这条链路的第二条腿 —— 「这几页不在菜单里」由不变式单独守。

45. **全量回归「没出判定就断」= 沙箱把整棵进程树杀了，不是你的代码**（v49，连中四次）：
    · 现象：`verify.py` 跑到 **2 分半左右**抛 `WebSocketConnectionClosedException`，
      **日志里连判定行都没有**；而且落点每次不同（一次断在 DRIVE 里 line 4042、
      一次断在截图阶段 line 4117）。同一份代码，**第一个 4 分钟跑完整绿**，之后连续四次全断。
    · 根因：Chrome 启动时会派一个子进程
      `~/Library/Application Support/Google/GoogleUpdater/152.*/GoogleUpdater.app/Contents/MacOS/GoogleUpdater --wake`，
      它周期性地删 `~/Library/Application Support/Google/RLZ/RlzStore.plist`、
      `~/Library/.../GoogleUpdater/*`、`~/Downloads/.com.google.Chrome.*` 这些**家目录**文件 ——
      而沙箱拦「家目录文件删除」会**把整棵进程树杀掉**（v27 记过一次，症状是「卡 2 分 02 秒」）。
    · **为什么 v27 的修法不够**：v27 只钉了 `HOME=/tmp/_cdp_home`。更新器删的 RLZ 那几条路径
      走的是 macOS 的 `NSHomeDirectory()`（CoreFoundation），**不看 `$HOME`**。
      必须同时钉 **`CFFIXED_USER_HOME=/tmp/_cdp_home`**（CF 专门给这类场景留的开关）才真挪得动。
    · 判读口诀：**「没出判定就断」先怀疑环境，别先怀疑自己刚改的那几行。**
      三条判据 —— ① 短探针（十几秒：开浏览器 → 进目标页 → 读几何 → 截图 → 退出）一切正常；
      ② 全量回归**固定在同一个时间量级**掉线；③ 命令行 stderr 里能看到那几条 `file-delete` 被拦。
    · 配套两个做法：
      ① 把回归包一层**自动重试**（跑到出现 `Z_DONE = ok` 为止，最多 3 次），
         别让一次偶发断线吃掉四分钟的等待；
      ② 能短就短 —— 本轮要反复看「筛选条折成什么样」，写了个 15 秒的短探针，
         改一版看一版。**长回归留给收尾，短探针留给自己迭代。**
