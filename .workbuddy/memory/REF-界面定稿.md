## 下载与导出（v17 新增）

界面上**所有**下载 / 导出入口（15 个）走同一条链路，实现在 `src/app.js` 的「导出」段（约 366 行，插在「初始化」段之前）。

```
点击 [data-dl="<key>"] → dlOpen(key, btn) → DL[key].build() 现算
  → showModal('下载确认', dlModalBody(b), '取消 + 确认下载')
  → 点 [data-dl-go] → DL_PEND 交给 dlSave()（Blob + a[download]）→ toast 已开始下载
```

- **`DL` 注册表 15 个键**：`samples / genes / samplist / unmatched / runlog / resultzip / patho / diffgenes / enrich / diffprot / diffmeta / alignmatrix / kbresult / trace / template`。每个带 `name / fmt / src / build`。**接后端只换 `build()`**，确认框与按钮一个字都不用动。
- **确认框里四件事写清**：文件名、格式 + 行数、体积、来源（哪一页从哪张表算的），外加一句说明（例：`表内 8 行 · 源数据全量 1,247`）。
- **动作列不导**：`DL_ACTION_COLS = ['操作', '处理方式']` 的列装的是界面按钮，整列丢掉 —— 留着空格子会让人以为数据缺了。
- **导出 SVG 前补 `xmlns`**：内联 SVG 没有它，拼进 ZIP 后单独打开是白屏。
- **ZIP 自己写（STORE 无压缩）**：CRC-32 查表 + Local Header / Central Directory / EOCD，条目名 **UTF-8（flag `0x0800`）**。导出结果 = 13 张 SVG + 19 张 TSV。先在 Node 里独立验证过（`crc32('abc') = 352441c2`），避免在浏览器里反复试错。
- **内置条目 vs 真实归档件**（样本资料卡）：内置条目只有元数据 → `dlSampDoc(i)` **直接 toast 说清「没有实体文件」，不弹确认框**（弹一个「确认下载」再告诉你没有文件，比直接说清楚更让人恼火）；新归档的真实文件才走 `DL_PEND + showModal`。
- **异常面板里的动作也能是下载**：`alertHTML` 支持 `x.dl` 分支；「下载格式模板」两处动作已从 `data-fix` 改成 `data-dl="template"`。改这个会连带影响 `anomP02` 段的探针 —— **测模板按钮必须在点「自动转成 .csv」之前**（修复动作会把整个面板换成已处理态，按钮随之消失）。
- 运行时探针：`__dlKeys` / `__dlOpen(k)` / `__dlPending` / `__dlBuild(k)` / `__dlBytes(k)`（ZIP 用 base64 带出交给 Python 复核）。

## 深色左栏与 L 形外壳（v18）

左栏底 = `--color-brand-deep` `#0A4655`；顶栏左侧一段同色同宽（`--rail-w`），两块拼成完整的「L 形」。

**结构**：

```
.topnav::before       ← 深色块：left:0 / top:0 / bottom:-1px / width:var(--rail-w) / z-index:0
│                        bottom:-1px 是为了盖掉顶栏那条 hair 分界线
│                        （不盖的话深色柱会被一条浅灰线拦腰截断）
├─ .topnav > .mobnav / .tnav-brand   ← 只有这两个在深色块里，显式 z-index:1
│    ⚠️ 不给 .topnav > * 通配：那会让 .topnav__side 也变 relative，
│       它内部的下拉面板原本相对 .topnav 定位，会整体跑位
└─ .crumb / .topnav__side            ← 在 x > rail-w，不受影响，前景色不用动

.tnav-brand { width: calc(var(--rail-w) - 16px) }   ← 右边框正压在深色块右缘（16 = 顶栏左内边距）
```

**色**（块内前景全部走 rail 一套，深浅底两套 token 不通用）：

| 部位 | 前景 | 对比度 |
|---|---|---|
| 一级分组 / 工作台 | `--color-rail-ink` `#EEF5F7` | 9.4 |
| 二级子项 | `--color-rail-ink2` `#BFD8DE` | 7.0 |
| 计数 / 页脚 | `--color-rail-ink3` `#9DBFC7` | 5.3 |
| 分组图标 | `--color-rail-accent` `#7FD0E2` | 5.9 |
| 当前项 | brand-soft 底 + brand-deep 字 | 8.9 |
| hover | `--color-rail-hover` `rgba(255,255,255,.10)`，字提到 rail-ink | — |
| 焦点环 | `.snav :focus-visible { outline-color: var(--color-rail-accent) }` | 默认深青在深底上 **1:1 等于没有** |

**两条硬约束**：

1. **`--rail-w` 是左栏宽度的唯一来源**，同时供 `.shell` 列宽与顶栏 `::before` 宽度；1400 / 1180 / 900 三档断点**也只改它**，`.shell` 不再自己写列宽。两处各留一份数值 → 「深色块比左栏宽 2px」这种只能靠眼睛找的问题。
2. **`is-railoff` 要同时挂 `.shell` 与 `.app`**（`setRail()` 里一行）：顶栏深色块与 logo 配色靠 `.app.is-railoff` 切换。不收的话白底上剩一根没有柱身的色块，而它文字是浅色 —— 「收起左栏」顺手把品牌区变成不可读。**没用 `:has()`**（少一层浏览器能力依赖）。

**验证口径**（`verify.py` 的 `R.railNav` + `R.railAuto`，9 条）：

- 不查「用了哪个 token」，**逐个可见文字元素算实际前景 vs 实际背景 ≥ 4.5**。深底压深字在 DOM 数据上完全正常（元素在、文字在、`aria-current` 也对），只有算对比度才暴露。
- ⚠️ **顶栏品牌区压在 `::before` 上，而伪元素不是 DOM 节点**：`effBg()` 沿 DOM 往上摸只会摸到 `.topnav` 的白底 → 把 9.4:1 量成 1.1:1 的假结论。那里必须显式 `getComputedStyle(q('.topnav'), '::before')` 取计算色当背景。
- 结构两条：深色块宽度 == 左栏宽度（±1）、品牌区右边框 == 深色块右缘（±1）。期望色从 `--color-brand-deep` 现算（`toRgb()`），不写死 rgb 字面量。
- `railoff` 两条：`.app.is-railoff` 为真 **且** `::before` 的 `display === 'none'`；品牌文字对比度仍 ≥ 4.5。

## 图表渲染：尺寸与替代视图（v19）

**统一通路**：`.chartbox[data-chart]` → `renderChart(host)` → `wrap(w,h,label,inner,maxW)`。
代理图返回 `{ w, h, inner, [legend], [table], [maxW] }`，`title` 兼作无障碍名（`aria-label`），
`showTitle:false` 用于「卡片头已写同名标题、图内不再重复」的情形（对齐矩阵）。

**尺寸**：`maxW` = 自然显示宽度上限，不传则维持 `width:100%` 铺满。传 `maxW = w`（viewBox 宽）即「绝不放大」，
多余宽度 `margin:auto` 居中。**为什么需要**：`width:100%` 按容器等比放大，倍率 = 容器内容宽 ÷ viewBox 宽 ——
640 宽度的图在 772px 卡片里只放大 1.21 倍（字号 11 → 13.2，在设计内），
但**对齐矩阵 viewBox 仅 416，放大到 1.86 倍**：图内 19px 数字变 35px（正文 14px 的 2.5 倍）、
整图从 366px 涨到 666px 高，把同页「未匹配样本」表顶出首屏。它是全站唯一 `viewBox < 500` 的图。

**对齐矩阵尺寸表**（`CHARTS.align`）：格子 104 单位（格内净宽 98）· 数值 19px（与指标卡 22px 同量级）·
轴标签 12px（与表格 12.5px 对齐）· 副标签 10px · 整体 416 × 366 居中于 772px 内容区。
卡片高度 756 → 492px。600px 视口以上完全恒定 1:1；375px 手机端缩到 0.743（副标签 7.4px，
但仍优于其它图 —— 640 viewBox 的图在手机上只有 5.3px）。

**曾经的破例**：对齐矩阵原先绕过 `renderChart` 直接 `host.innerHTML = wrap(...)`，因此
**尺寸无上限**（放大 1.86 倍）**且没有其它 13 张图都有的数据表替代视图**（3×3 的 75/71 对读屏用户完全不可得）。
收进 `CHARTS.align` 后特例消失。**教训：特例图是「尺寸约束」与「无障碍替代」两条约定同时失效的地方**，
新增图一律走 `CHARTS` 注册表，并顺带体检「全站有多少张图没走统一通路」。

**验证口径**（`verify.py` 的 `R.alignMatrix` + `R.alignAlt`，6 条）：
量**屏幕实际字号** —— SVG `text` 的 computed `font-size` 返回 **viewBox 单位**，
必须乘 `实测宽 ÷ viewBox 宽` 才是用户看到的字号（不乘会得出「字号一直很正常」的假结论）。
判据：缩放比 ≤ 1.05 · 数值字号 14–24px · 最小字号 ≥ 9px · 9 格数值齐全 ·
替代视图 3 行 4 列 · 可展开且首行与图同源（`基因组|75|71|71`）。

## 自编排画布（v21）

**位置**：p04「流程模板」页第 2 节，标题**自编排流程**（原「选或编排流程」）。

| 部位 | 落点 |
|---|---|

| 画布唯一事实来源 | `CANVAS = { base, nodes, links }`；`loadFlow(id)` 灌初值，模板不再被回写 |
| 点工具 | `[data-tool]` → `appendNode(name)`（追加节点 + 补一条末端连线）+ `openToolDrawer()` |
| 重置 / 保存 | `[data-orch-reset]` → `resetCanvas()`；`[data-orch-save]` → `saveCanvas()`（`FLOWS.push({saved:true})`，id 从 `f2014` 起） |

| 缩略图 | `.dagmini`，画布两列网格的**第二列**（不是绝对定位） |
| 运行时探针 | `__orchPick(id)` / `__orchForget()` / `__orchState()` |

**三条硬约束**：

1. **`FAI[name].p` 已经是完整的 `<path …>` 标记**（build.js 存 innerHTML）。写 `'<path d="' + d.p + '"/>'`
   会把属性截断，余下的 `"/>` 变成画布上的**可见文字**。正确写法是直接拼 `d.p`。
