### 顺带修掉的真 bug：幽灵抽屉（重要）

`openSampDrawer()` 原先写「`!hidden` 就 return」。关闭是**先摘 `is-open` 播 0.26s 动画、
300ms 后才 `hidden`**，所以在这 300ms 内再打开 → `clearTimeout` 撤了收尾、提前返回又让
`is-open` 加不回来 → 抽屉永远停在**屏幕外**，而 `getBoundingClientRect().height` 正常、
`hidden === false`、DOM 数据全对，**只有 `elementFromPoint` 返回 `null`**。

- 表现：切到基因 tab 再切回来、其间点到列表行 → 抽屉再也不出来
- 修法：「开着」= `!hidden && .is-open`；提前返回条件 = `was && .is-open`；先 `clearTimeout`
- 这一条是**先被验证脚本量出来的**（`linFold0.hit = {ok:false, got:'(null)'}` × 3 处同时红），
  一开始以为又是「没滚进视口」的老毛病 —— 不是。同一个按钮在干净状态下量得到，
  说明是**某段之前的操作把它挪到了屏幕外**。

### 血缘图宽度：写死 1100 → 按容器实测

`LIN_MAXW = 1100` 换成 `linMaxW()`（读 `#linBox.clientWidth`，收起时回退 804，clamp [560,1100]）。

### 卡宽与槽距必须**联合求解**

上一轮纵向的写法是「先算槽距 S，不够大再把卡缩到最小系数 0.7」。抽屉里 S 被压到 173、
卡缩到 175 → **卡比槽距宽 2px，三张衍生模型叠在一起**，而一眼看不出是重叠。
正解：`NW = S − LINGAP` 代进 `span ≤ maxW` 解出 `S ≤ (maxW + LINGAP) / 叶子数`。
横向列式同理。两处共用 `linFit(可用宽, 自然宽)`，`LINGAP = 22`。
实测三种样本两个方向，**留白全 ≥ 22、scale 全 1.000**。

### 搬家的副作用：三类检查静默放宽（都在本轮修掉）

| 检查 | 退化 | 修法 |
|---|---|---|
| 表格居中探针 | 抽屉收起 → 表 `display:none` 被跳过：表数 6→4、列数 38→24 | 量前先 `__sampDrawer(true)` |
| 截图 | `scrollIntoView` 只滚抽屉内部、页面停在顶部 → 拍成「列表 + 空白」 | 先 `__sampPick()` 让它自动滑出再滚 |
| 命中测试 | 元素在屏幕外 → `(null)` | 同 + `hitOK2` 自带 `scrollIntoView` |

顺带清掉一批**写死容器宽**的旧断言（`vb[2] == 1000`、`cardW == 250`、`cardW == 176`），
换成「等分 + 落在容器内 + 同层留白 ≥ 12」这类与住处无关的不变式。

### 教训

1. **浮层有第三态**：`hidden` 与 `is-open` 必须一起查。凡「先摘类播动画、延时才 hidden」
   的实现，都要测「关到一半再开这一条路径」。
2. **搬家改动要回头问一句**「原来量它的那些探针，现在还够得着吗」—— 不动声色地少量几条，
   比报红更危险（`>= 38` 那次就是被当成「阈值该调小」）。
3. **两个量互为约束时别分开各算一次**（卡宽 / 槽距）。分开算的结果是「各自都在合理范围内、
   合起来越界」，而屏幕上表现为一种说不清的不对劲（卡挨着卡）。
