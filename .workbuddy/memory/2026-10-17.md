**build 自检判据的精度修正（不是放宽）**：原判据「产物文本里有任何 http:// = 外部请求」把「用户点击才发起」误判成「加载即发起」。改为按**发起时机**分类：加载即发起必须 0；点击才发起（`a[href]`）豁免但要有**白名单** `EXT_OK`。豁免的落地是**按语义定位**（摘掉 `a[href]` 与 `ext` 数据字段整段再看），不是补正则 —— 补正则只会漏得更隐蔽。

**认知修正**：外链 `<a href>` 是**运行时**由 `NAVGROUPS.ext` 拼出来的，静态 HTML 里只有 `href="' + esc(grp.ext) + '"` 模板 → 「页面上真有这个入口」**只能靠运行时探针**，静态检查一律断不了。

## v58：知识赋能三页 → 页内挂载外部知识系统

**需求**：用户要「换一种接入方式」——把医学知识库/自有知识库/知识图谱分别对接到 77.144 的 `/ke` `/kb` `/kg`，**去掉 menu 参数**，在**右侧工作区**展示外部页面、保持左侧菜单布局，使其「更像一个整体」。这是**替换** v57 的组标题跳外链方案。

**先验证前提再动手（最值钱的一步）**：跨域 iframe 有绕不过的硬约束 —— 外部系统可用 `X-Frame-Options` / CSP `frame-ancestors` 拒绝被嵌套，那是响应头，前端无解。`curl -D` 实测三个路径均为 200 + `text/html` + **两条头都没有** → 可挂载。顺带发现：带 `?menu=1` 时探测不通、去掉后 200，印证「去掉 menu 参数」本身就是必要的。

**两个用户已确认的决策**：① 页头加「外部系统 / 站内版本」切换，**站内那份保留**（整页替换会让 24 条断言对应的能力消失，且内网不通时三页变白板）；② 加载失败显示**真实可点**的重试/另开，不编造内容。

**关键实现**：`KB_EXT_BASE` + `KB_EXT{kbmed:/ke, kbown:/kb, kbgraph:/kg}` 为地址唯一来源；视图切换用 `hidden` 收放**不换页**（换页丢滚动位置 + 面包屑多一级）；iframe 由 `mountKbFrame()` 动态 `setAttribute('src')` → **产物 HTML 里根本没有 src 属性**，静态检查一律断不了，只能靠运行时探针。

**失败态必须有 setTimeout 兜底**：iframe 的 `load` 在**被拒绝时根本不触发**（X-Frame-Options 拒绝、连接失败、DNS 不通都是直接拒绝）→ 「没等到 load」本身就是失败信号。不加兜底的话失败态永远不显示，用户只看到白板，连「是网络问题还是系统坏了」都判断不了。

**断言刻意不断「iframe 加载成功」**：跨域读不到，且目标是内网地址，成败取决于**跑回归的机器有没有接内网** —— 那是环境不是缺陷，写进断言等于埋一颗「换台机器就红」的雷。

**踩坑 1（批量替换误伤，栽了一次）**：为 iframe 区把 `data-kbopen` 改名 `data-kbframeopen`，用的是整文件 `str.replace` —— 连**站内知识库原有两处渲染 + 一处事件委托**一起改了。表现不是立刻报错，而是驱动跑到 `#kbPanel [data-kbopen]` 那行才 `q()` 返 null 崩掉，而真因在几百行外。**改名只动自己新加的那几处；替换后 grep 新旧两个名字，确认旧名的原有处数没变。**

## v59：内置数据集封面图裂（用户报「工作台的内置数据集封面图不显示了」）

**根因（构建期，不是部署问题）**：`build.js` 的注入顺序反了 ——
先把 `window.IMG_URI={…}` 注入产物（键=`assets/xxx.jpg`），**再**做「`assets/xxx` → base64」
的全文档 split-join 替换，于是**映射表的键名也被替换成了 base64**：

```js
window.IMG_URI = { "data:image/jpeg;base64,/9j/4AAQ…": "data:image/jpeg;base64,/9j/4AAQ…", … }
```

`assetAbs(p)` 查 `IMG_URI['assets/'+p]` 必然落空 → `|| k` 静默退回相对路径。

**为什么本地看不出来**：`prototype/` 旁边就有 `assets/`，相对路径照样出图、591 条回归全绿；
`deploy-static/` 只有 `index.html`、**没有 `assets/`** → 整片图裂。
「查表失败就静默降级」把构建缺陷伪装成了部署环境问题。

**修法（build.js）**：① 注入处只埋 `<!--INJECT_IMG_URI-->` 占位，所有替换做完再函数式回填；
② base64 只算一次（`IMG_DATA` 复用）；③ **顺带修好 CDN 版** —— 原来 `IMG_URI={}` 留空也是错的
（注释推断「退回相对路径配合 CDN 图源仍能显示」不成立：远程 URL 是构建期拼的，运行时没人替换它），
改为注入远程 URL 表 `IMG_REMOTE`；④ 自检改为**解析 `window.IMG_URI` 断键名/条目数/值前缀** ——
原自检 `off.includes('"'+k+'"')` 在这个 bug 下反而全绿（它以为已内联干净）。

**新增断言（3 条，588 → 591）**：`__pubds()` 探针加 `imgUriKeys`/`imgUriKeyAllPath`/`resolveHit`/
`coverSrcKinds`/`coverLoaded`/`coverSize`。**关键认知：「有 `<img>` 元素」≠「有图」**，
v40 那条只数 `.dcard__im` 元素个数，而元素一直都在（只是图裂）→ 断不出来。
必须读 `naturalWidth > 0` + src 前缀是 `data:`。verify.py 侧与 build 侧都要断，
**「查表命中 0 就静默降级」的故障类型必须断查表本身**。

**回归 591/591 全绿**（无浏览器异常）｜截图 91 ｜标注 34 ｜产物 5,240,249 字节
（比 v58 少约 33 万 —— 映射表不再被二次膨胀，每个键原本都是一份完整 base64）｜md5 `f6aa0b03…`。
还原点 `_backup-v1/v59-imguri/`；文档 §51。`deploy-static/` 已同步，**待用户确认后发布**。

**通用教训**：`offline.split(k).join(uri)` 这类**全文档字符串替换**会把任何刚注入的、
