### 关键设计决定：原「画布全屏放大」不撤

「全屏」按钮原职责是放大站内画布（v21 起，DAG viewBox 等比缩放，铺满后节点文字才读得清），
**有 13 条断言正断着它**。直接改成「全屏 = 进外部系统」等于连根拔掉。做成两视图共存：

```
点「外部编排」→ #orch 铺满视口 → .orchext 接管、站内画布收起
   └─ bar 上「返回站内画布」→ 同一全屏壳里换回画布（仍全屏放大）
再点「收起」/ Esc / 跳页 → 整体退出
```

`setOrchExt(on)` 与 `toggleOrchFull(force)` **正交**：全屏管尺寸，外部视图管内容。
退出时两边一起复位，否则下次进编排页是块白板。

### 复用 v58 iframe 模式（不另立一套）

`ORCH_EXT_URL` 是地址唯一来源；`src` 由 `mountOrchExt()` 运行时 `setAttribute`
→ **产物里没有 src 属性**，只能靠运行时探针 `window.__orchExt()` 断；
`setTimeout(8000)` 兜底判失败（`load` 在被拒/超时时根本不触发）；
**刻意不把「iframe 加载成功」写进断言**（能否达取决于跑回归的机器有没有接那个网络）。

### 两个 CSS 坑

1. **`.orch__b[hidden]` 必须显式声明** —— 它是 `display:grid`，UA 的 `[hidden]{display:none}`
   压不住类选择器，缺这条等于没收画布、外部系统与画布叠在一起。
   `.orchext[hidden]` / `.orchext__ph[hidden]` / `.orchextfail[hidden]` 同理各自声明。
2. **`.orch.is-full .orchext` 要 `flex:1; min-height:0`** —— flex 子项默认
   `min-height:auto`，否则 iframe 内容高撑破容器、全屏壳里出双滚动条。

### 两条红各有不同性质（都值得记）

第一次跑 **601/603**，两条 FAIL：

- **`默认视图是站内画布`** ← **实现 bug**。`data-orchview` 只在 `setOrchExt()` 里写，
  而初始态从没调过它 → 没进过全屏的编排页上它是 `null`。
  修法：`initOrchExt()` 末尾显式 `setOrchExt(false)` 落一次初始态。
  **教训：判据属性必须有初始值，不能只在状态切换时写** ——
  否则「默认值是什么」这件事在 DOM 上没有任何证据，只能靠假设。
- **`外部系统 iframe 铺满全屏`** ← **我断言写错了，不是实现错**。
  写成 `iframe 高 == 容器高`，但 bar 与 iframe 是**并列 flex 子项**，
  iframe 天然矮一个 bar 的高度（实测 955 vs 1000）。
  改判据为：`|iframe高 − (容器高 − bar高)| ≤ 2` **且**紧贴 bar（gap ≤ 2）**且**底部无余量
  （slack ≤ 2）**且**吃掉视口 ≥ 90%。**教训：并列 flex 子项之间不能直接比父子高度。**
