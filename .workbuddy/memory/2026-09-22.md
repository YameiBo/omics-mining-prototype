## 2026-09-22 · p04「选或编排流程」加全屏放大开关

**需求**（用户原话）：「选择分析流程的页面，第二部分 选或编排流程 部分增加一个可以全屏放大的按钮，点击可放大或收缩，以便更方便设置」

**为什么全屏在这里是刚需（不是装饰）**
DAG 用 `viewBox` + `.chart{width:100%}` 等比缩放。中栏约 668px 时，7 节点流程的 viewBox 宽 1046 → 只放大到 **0.64 倍**，节点文字被压到 ~7px，基本没法读。全屏后按窗口宽度放大到 **1.09 倍**（实测画布 844px → 1138px），这才谈得上「方便设置」。

**落地 6 处**（按项目「新增模块落 6 处」的规矩）
1. **图标登记**：`app.js` `ICON_REGISTRY` 加 `expand` / `compress`（FontAwesome 69 个图标）。
2. **HTML**：`.orch__bar` 右侧按钮组最左加 `<button class="btn btn--sm" data-orch-full aria-pressed="false" aria-label="全屏放大编排区，便于查看与设置流程">`。
3. **CSS**：`.orch.is-full { position: fixed; inset: 0; z-index: 58; ... }` + `body.is-orchfull { overflow: hidden }`。
4. **JS**：`toggleOrchFull(force)`；事件委托分支；Esc 处理；`goto()` 里收敛。
5. **verify.py**：新增 `R.orchFull` 共 **15 条**断言；并把手写断言整段搬进脚本末尾（见下）。
6. **截图**：新增 `24-orch-full.png`。

**四个设计决策（都写进了代码注释）**
- **z-index 取 58，刻意低于遮罩 60 / 抽屉 61**：这样全屏里还能弹出工具配置抽屉。断言 `drawerAbove.ok` 把「全屏不遮挡抽屉」钉死 —— 若以后有人图省事把 z-index 提到 70，断言会红。
- **`toggleOrchFull()` 状态没变就 return**：`goto()` 每次导航都会调它来收起全屏，若每次都重写按钮 `innerHTML`，会把焦点和选中态一起抖掉。
- **Esc 分层**：先判断本轮有没有开过浮层（modal / popTask / trace / tool / hist / agent / 移动端 snav），**都没有开才退全屏**。否则在全屏里点开工具配置后按一次 Esc 会连退两层。为此把原 Escape 处理器改成「先算 `hadOverlay` → 再统一收 → 最后按需退全屏」。
- **跳页自动收起**：`goto()` 里调 `toggleOrchFull(false)`。全屏是「就地放大」，跳走还留着会盖住新页面。

**一个视觉返工（自己看截图看出来的）**
第一版全屏里 DAG 顶部对齐，下方空出 ~345px，看着像没做完。改为「图 + 图例」这一组垂直居中：
```css
.orch.is-full .orch__canvas { display: flex; flex-direction: column; }
.orch.is-full .orch__canvas > .dagwrap { margin-top: auto; }
.orch.is-full .orch__canvas > .daglg   { margin-bottom: auto; }
```
用自动外边距而不是 `justify-content: center` —— 内容超高时自动外边距归零，不会出现 flex 居中裁掉顶部的老问题。实测上下各 345px。

**没做的两件事（想清楚后放弃，记下来免得下次重走）**
1. **没有「全屏时自动展开节点列表」来填空白**。虽然有 345px 空闲很诱人，但节点列表的定位是 DAG 的**数据表替代视图**（替代，不是并列）—— 同屏既给图又给表违反项目「同一事实只讲一遍」。空白是「宽而扁的 DAG（约 1048×178，5.9:1）」在 1440px 宽下的必然结果，居中即可，不该硬填。
2. **没有做「点 DAG 节点 → 打开该步骤工具配置」**。`dagSVG` 生成的 `.dagstep` 带 `role="button"` + `tabindex="0"` + `cursor:pointer`，但**从来没有点击处理器**（查过 `_backup-v1/app.js.pre-v3`，v2 时代就是这样，不是 v3 引入的回归）。想做，但评估后放弃：流程节点是展示名（"fastp 质控"），工具库是工具名（"fastp 快速质控" / "fastp 双端质控/去接头"），**Token 打分匹配 65 个节点里 15 个落空、且多个是真歧义**（两个 fastp、两个 FastQC 打平）。硬凑映射会在客户评审现场给出错误信息，代价大于收益。已在回复里把「去掉假按钮语义」和「补一份显式别名表」两个选项交给用户定。

### 二、顺手抓到的真事故：四个宽表页整页渲染成**空白**

**根因**（写 CSS 时完全想不到的一层）：

```js
pageW: Math.round(q('#page-log').getBoundingClientRect().width),
```

```python

     and bodyW >= vp * 0.9 and pageW >= vp * 0.9, railAuto)
```
**通则（已写进 MEMORY.md §4-8）**：凡「收起 / 折叠 / 隐藏」类交互，断言里必须有一个**真实像素几何值**（宽/高/可见面积），不能只有 class 与 textContent。

## 2026-09-22 · 页面返回入口 + 面包屑可点

**需求**（用户原话）
> 1、每一个页面都需要有返回上一步或者返回主页面的按钮；
> 2、通过点击系统顶部的面包屑也可以返回相应的页面。

### 一、「返回上一步」= 来路栈，不是流程上一步

`NAVHIST`（来路栈）+ `NAVCUR` + `NAVSILENT` 三个变量，`goto()` 里入栈。
- **同页重入不入栈**：连点两次「工作台」不该把它压两次。
- **`goBack()` 自身不入栈**（`NAVSILENT`）：否则返回后会把刚离开的页又压回去，来回打转。
- **不维护完整历史树**：演示里「返回」的心智模型就是浏览器后退，「从哪来回哪去」最不容易误判。按钮 `title` 写明目标页名（「返回上一步：流程模板」），点之前就能预知去向，不让「返回」变成盲盒。

### 二、两个入口互斥显示（这是产品判断，不是实现细节）

| 状态 | 「返回上一步」 | 「返回工作台」 | 整条 |
|---|---|---|---|
| 工作台 + 栈空 | 隐藏 | 隐藏 | **收起** |
| 别的页 + 栈空 | 隐藏 | 显示 | 显示 |
| 别的页 + 上一步是工作台 | 显示（指向工作台） | **隐藏** | 显示 |

## 一、弹窗消失的根因：遮罩绘制在弹窗主体之上

```html
<div class="modal" style="position:fixed; inset:0; z-index:70">  <!-- 自己成了层叠上下文 -->
  <div class="back" style="z-index:60"></div>                     <!-- 遮罩 -->
  <div class="modal__b" style="position:relative"></div>          <!-- z-index:auto -->
</div>
```

`.modal` 的 z-index:70 让它成为层叠上下文；内部 `.back` 的 60 与 `.modal__b` 的 `auto`

- 脚本用 `el.value = x` + `el.click()` —— **不经过命中测试**，直接调用事件处理器；
- 截图里弹窗只是被蒙了层灰，**反而更像"正常的模态"**。

**修法**：`.modal > .back { z-index: 0 }` + `.modal__b { z-index: 1 }`。
**只改 .modal 内部这一处** —— `#backTool` / `#backTrace` / `#backProj` 的 `.back`
是抽屉的顶层兄弟节点，靠 60 < 61 本来就正确，一起改会把对的地方弄坏。

# v10 · 返回条精简：与面包屑去重

> 需求原话：「优化每个页面上的返回上一步的按钮，部分页面可去掉；可以通过点击页面顶部的面包屑来返回即可，不用重复」

## 一、把「不用重复」翻译成一条可判定的规则

用户说「重复」，但**按按钮逐个删是错的** —— 先问「这一跳面包屑能不能做到」：

| 来路 | 面包屑够得到吗 | 返回条 |
|---|:---:|---|
| 无来路 | — | 收起 |
| 正是面包屑某段的落点 | 能 | **收起** |
| 够不到（横向跳转） | 不能 | 显示「返回上一步」 |

判据一句话：`prevId ∈ crumbSegs(NAVCUR).map(s => s.id)`。
于是顺菜单 / 顺流程点进来的页面根本没有返回条，只有横向来路（数据集页 → 项目页）才出现。

**「返回工作台」按钮全撤**（15 处返回条 + p02 页脚 1 处）：面包屑第一段就是它。
撤掉后必须显式决定**清栈语义去哪** → 面包屑那一段刻意**不清栈**（点回工作台还能退回原页），
`goHome()` 保留给验证脚本当「状态归零」，不接 UI 入口。

## 二、判据必须与面包屑**共用同一份数据**

新增 `crumbSegs(id)`：`renderCrumb` 按它生成、`renderBack` 按它判断「来路是否被覆盖」。
两处各写一遍必然漂，而漂了以后出现的组合恰恰是断言看不出来的那种 ——
**「按钮收起来了、面包屑却回不到那儿」**，两侧各自都自洽。
并暴露 `window.__crumbSegs` 给验证脚本：断言「该不该收起」必须能**独立算出**，
照抄产品判据就只测出自洽、测不出对错。

## 三、顺手修掉两类「死段」（同一次动因）

面包屑上点了会回到当前页的段：

| 情况 | 页面 |
|---|---|
| 该分组只有它一个页面 | 样本档案（数据资产）、运行日志（系统管理） |
| 当前页就是该组首项 | 数据采集 p02、项目管理、医学知识库 |

判据 `g.items.length > 1 && g.items[0].id !== id`。**「不存在」靠不生成来表达**，
与「起点不生成祖先段」同一手法。留个死段比没有它更糟 —— 用户点一次没反应，
就再也不信面包屑上任何一段是可点的了。

## 七、方法论：样式改动的断言要「断两侧 + 断几何」

4. **标签不带限定词**：`组织 RNA 完整性` 撑破 108px 列宽换行 → 改 `RNA 完整性`
   （分组标题「质控信息」已经限定了上下文）。

## 六、方法论：给「可写」功能写断言

静态页面的断言问「渲染对不对」，可写功能的断言要问**「点完之后数据有没有真的变」**：

- **非法输入三种都要断**：空值 / 非法字符 / 唯一性冲突。只测成功路径等于没测校验。
- **保存后要回读卡片上显示的文本**，不能只看 toast —— toast 成功而数据没落，
  是最常见的假象。
- **「先列表、后提交」的中间态要断**：待归档清单存在、且能撤掉一条，
  这才证明「点归档才写库」这句话是真的。
- **空态单独断**：新登记样本的跨组学表必须是「尚未产出组学数据」，而不是顺着算出来的
  「0 路组学 · 分布在 0 个项目」—— 后者读起来像「算过了，结果是 0」。
- **每引入一类新控件，就补一条「中心点能被自己接住」**（`elementFromPoint`）：
  遮罩压主体是这个项目踩过的坑，而 JS 设值 + JS `.click()` 永远抓不到「点不动」。
