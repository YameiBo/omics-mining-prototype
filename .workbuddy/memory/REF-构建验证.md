# 构建与验证的必留守卫（天中医原型专用）

> 从 `MEMORY.md` 拆出。通用验证教训见技能 `static-prototype-verify`；界面定稿细节见 `REF-界面定稿.md`。
> **改 `src/` 之后、跑 build/verify 之前扫一眼这里。**

## A. 构建链守卫

1. 注入用**函数式替换** `() => js`；断言产物 JS 与 `src/app.js` 逐字节一致、`$$(` 计数 == 源码计数（**不写死阈值**）。扫 `closest('[data-*]')` 是否命中 `<body>`/`<html>` 自身属性（被祖先吞掉 → 其后事件分支不可达）。
2. `tw.css` 必须含 `svg.ico{`；离线版必须已内联 `assets/*.jpg`。**禁止 `.chartbox svg{width:100%}`**，必须 `.chartbox svg.chart`（会把「查看数据表」按钮里的图标撑成 300×300 蓝块）。
3. **`app.js` 里禁止字面量 `<i class="fa-solid …">`**，一律 `ico('name')`（`inlineIcons` 在 JS 注入后执行会改写它 → 离线/在线两版 JS 分叉）。
4. **所有 `id` 必须是合法 CSS 标识符**；扫 `id=` 前先剥 `<script>`。
5. **「界面无演示字样」守卫**：HTML 剥标签、JS 剥注释后查「演示」。**`body.textContent` 会把内联 `<script>` 注释算进去** —— 必须先克隆 body 删 script/style，否则 JS 注释里的「演示」全是误报（代码注释里保留「演示」是有意的，对开发有效）。
6. **改 `ICON_REGISTRY` 只追加不删**：图标名散在 `ico('x')` 与数据字段（`TOOLCATS.ic` 等）两处，凭「哪里还在用」的感觉删必错（已踩：`table-cells` / `play` / `dna`）。漏掉的静默渲染成问号占位。
7. **告警是状态驱动的（v13）**：`CTX`（miss/n/queued/load）+ `syncAnoms()` 在 goto 时重算。**不要再加「演示某个异常」的按钮** —— 界面会回到 Demo 气质，且告警与真实操作脱钩。

## B. 断言写法

8. **隐藏 / 视口外元素几何恒为 0**：① 图标尺寸断言必须**逐页扫描**，否则隐藏页缺陷全程隐身；② 判「是否展开」用 `getComputedStyle().display` 而非几何，且**跨页共享的状态位（如全局折叠开关）必须跨页验**；③ 读几何 / 命中前先滚进视口（视口外 `elementFromPoint` 返回 `null`，**伪装成「点击无效」**）。
9. **「显示/隐藏」必须断言真实像素几何**：**`.btn` / `.ptab` / `.tag` / `.chip` 都是 `display:inline-flex`，会压掉 UA 的 `[hidden]`**（该收没收而属性值查起来还是 `true`）。新增可隐藏控件必须逐条写 `xxx[hidden]{display:none}`（不要全局 `!important`）+ 几何断言。
10. **探针三坑**：① 会切页的段**收尾必须回位**（否则后面量几何得 `0×0`，而存在性断言照样通过）；② **段首起点必须显式设定**（继承上一段状态 → 断言碰运气）；③ `<g>` 等 SVGElement 没有 `.click()`，要 `dispatchEvent`。
11. **断言全绿 ≠ 截图是对的**：`shot()` 按文件名查 `SHOT_PAGE`，未登记判不合格 + 反向断言「登记了的都产出」。现 **48 张**。
    ⚠️ **截图改名 / 作废后必须清 `.shots/`**：旧文件名残留会被反向守卫（「登记的截图全部产出」）之外的第一个守卫抓到 —— `27-back-nav.png` 改成 `27-crumb-nav.png`、删 `39-back-covered.png` 时踩过。清截图只在改文件名时才需要（同名会覆盖；一个 turn 内删 >50 个会触发确认）。
12. **「被遮蔽的通过」比 FAIL 更危险（v14）**：断言扫「当前页面上出现的状态值」时，页面内容一换被测对象就换了（ok/warn 只有 3.88:1 却一路绿灯）。**断言必须指定被测样本与字段**。
13. **断言两侧必须是同一条件**：跨样本 / 跨页面比数字前先问「这两侧本来就该相等吗」（曾用「展开后高 ≈ 折叠前」验复位，可中间切过的样本本来就矮 142px —— 功能是对的、断言是错的）。
14. **命中测试不要绑具体数据**：`hitOK2('[data-samp-pick="S068"]')` 应写成 `hitOK2('#sampChips .chip')` —— 验的是「控件点得动」，不是「某个 ID 恰好在里头」。
15. **数据从「手写几例」改成「生成一整段区间」时，回头查脚本里有没有假定某个 ID 不存在**（生成器造出 S069 撞掉补登用例，11 条连带失败）。
16. **python 判定段注释一律用 `#`**：往 verify.py 加段注释时误写 JS 的 `/* */` 已犯六次（语法错误让 `py_compile && build && verify` 短路，build 都不跑 → `window.__xxx is not a function`）。**改完 verify.py 第一件事就是 `py_compile`**。
17. **DRIVE 脚本里的辅助函数一律前置（v17）**：`verify.py` 的 `DRIVE` 是一整段 `async IIFE`，`const hitOK / hitOK2 / lastToast` **统一定义在脚本开头**（`const txt = …` 之后）。
    在中间某段用到而定义在后面 = **TDZ**：`Cannot access 'lastToast' before initialization`，而且**报错位置指向使用处、不在定义处**，排查很绕（会以为是新加的段写错了）。新增段要复用已有辅助函数前，先确认它在前面。
18. **别把「当前数据量」写死在断言里（v17）**：样本档案段会**补登一例 S076**，其后任何 `== 75` 的导出 / 计数断言都会挂。改成从 `window.__sampState().n` 现算。
    顺带纠正口径：导出的「同源」= **与当前档案条数一致**，不是「与 p03 队列 75 一致」—— 补登的新样本还没入队，两者本就允许不等。
19. **被测实现改了文案，断言要跟着改成「更有意义的判据」，不是把期望值也改掉**：`geneLastText()` 压缩后不再带证据条数，原断言 `'184' in last` 挂掉。**不要**把期望值改成 `'312'` 了事 —— 改成断言**状态条数字 == 抽屉结果卡数字**（从「重算 N 基因」正则取数），既守住「页面与抽屉同源」这条本意，也比「在整串里找子串」稳（老写法可能命中日期里的数字）。
20. **点开确认框 / 抽屉的那一步会不可逆地改掉面板**：`anomP02` 里「下载格式模板」按钮的测试必须放在点「自动转成 .csv」**之前** —— 修复动作会把整个面板换成已处理态，按钮随之消失，之后再数 `[data-dl="template"]` 个数就是碰运气（可能命中别的页里残留的同名节点）。

## C. 数据一致性

21. **「同一事实只讲一遍」**：展示字段与结构化字段并存时（如 `m:'… 9 条流程'` vs `sm/u/rn`）→ **删展示字段、改派生函数现算**。单位随数据走。智能体话术里的数字**存函数、提问时求值**；静态 HTML 里做不到现算的（`#projCount`、三个阈值展示值）→ 加**构建守卫**，并**反向验证过它会响**。
22. ⚠️ **并行编辑同一文件只有最后一个落盘**（工具仍回报 success）；改同一文件必须**串行**。
23. **导入 / 导出一类「产出物」要验「能不能被外部工具打开」，不是「字节数是否为 0」**：导出结果打的是真 ZIP，断言把 `__dlBytes('resultzip')` 的 base64 交给 Python `zipfile.ZipFile(...).testzip()` 复核（还查条目数、SVG 补了 `xmlns`、TSV 首行含 `\t`）。同理：导出的表要能被标准解压器 / 表格软件打开，光改扩展名不算。

## D. 增 / 删模块的固定动作

顺序：**清单 → HTML → JS → CSS → 构建/验证脚本 → 重建 → 全量验证**。

- **新增模块落 6 处**：① 数据层 ② 渲染函数 ③ 事件分支 ④ `init()` 调用 ⑤ 页面区块 ⑥ 样式。**漏 ④ 最隐蔽**（页面正常、静态看着对，但区块永远空且不报错）。
- **新增列表类模块**还要落：筛选下拉选项**从数据现算**（写死则新值筛不到）、列表状态归零接口（如 `__sampReset`）、渲染函数接入主渲染与选中函数。
- **重命名 / 重组左栏**同改 **8 处**：`NAVGROUPS` / `PAGES` / `STEPS` / 各页 `phead__eye`·`h1`·`d` / **跨页文案**（toast·note·alert·弹窗·智能体话术·导出文件名）/ `data-go` / `build.js` 的 `pages` / `verify.py` 逐页循环 + 面包屑断言 + 截图。改完**全文件 grep 旧名（含注释）**。
- **左栏是两级折叠树**：`NAVGROUPS[i].g === ''` = 顶级叶子项。**`navlist-gN` 的 N 是 `NAVGROUPS` 下标（含「工作台」），与 `.snav__grp` 下标差 1** → 用 `aria-controls` 取 id。
- **删除先列「牵连清单」**：① `#page-xx` 区块 ② 左栏入口 ③ **其它页面指向它的入口** ④ `PAGES` 路由表 ⑤ 描述它的文案。用**带断言的锚点脚本**（`s.count(a) == 1` 再切）。**删完补守卫防复活**。
- **详情类内容一律进右侧抽屉**（z 61；modal 70），不新开页面。
- **一次性补丁脚本**：自检写在写盘之前、**禁止用 `assert`**（早退会「既没改也没提示」）；锚点**整行替换最稳**。

## E. 其它通用约定

- **卡内要放按钮时卡片不能再是 `<button>`**；操作条常驻可见，不做 hover 浮层。
- **标了 `role="button"` 就必须真有处理器**，且 click 与 Enter/Space 两条路径都要有。
- **事件委托的先后即优先级**：内层按钮分支必须写在外层容器分支之前。
- **CSS 按「是否只属于被删页面」判定，不能按名字猜**。新增状态色/字色先算对比度（ink3 白底仅 3.44:1，不可用于小字）。
- **按「结构锚点」批量插入前先验证锚点覆盖全部目标**；**页数一律按 `qa('.page').length` 数**。
- **截图**：会开浮层且不关的**排序列最后**，每张 setup **开头先关掉上一张的浮层**；要看下方内容须 `scrollIntoView({block:'start'})`；**截图前先归零状态**（否则拍到上一段的筛选/排序）。
- **新增元素必须一并断言**：对比度、数量与内容、**三态流转**、联动副作用。**状态类组件把「尚未开始」当显式状态**；数字统一 `fmtNum()`；复用渲染函数要容忍字段 undefined。

## 布局改版时，写死像素的旧断言会跟着碎（v23）

「血缘谱系默认展开 boxH > 300」是纵向四层（约 500px）时代的阈值；改横向列式后
3 行是 284、1 行 132 —— 图的高度变成「列数 × 每列行数」的函数，任何写死的像素都会在
下一次布局改版时碎掉。改版时把这类断言换成两种不会碎的写法：

1. **绑现算值**：`boxH == viewBox[3]`（顺带钉住「没被容器拉伸」）；
2. **写结构不变式**：`scale == 1` 且容器宽 > viewBox 宽、列 x 坐标等差（步长 = viewBox 宽 ÷ 列数）、
   边的 `d` 里不含 C 命令（退回贝塞尔即露馅）。

别把阈值调小了事 —— `> 300` 调成 `> 120` 下次 1 行的图照样碎，而且碎得毫无意义。

## 命中测试前先 `scrollIntoView`（v24）

`elementFromPoint` 用的是**视口坐标**，元素不在视口内一律返回 `null`。
血缘卡在样本档案页中段，探针没滚进去时把好好的按钮量成 `hit: '(none)'` —— 差点当成
「画成按钮却点不动」的假交互去修。判据模板：

```js
const t = () => { el.scrollIntoView({ block: 'center' });
  const r = el.getBoundingClientRect();
  const e = document.elementFromPoint(r.left + r.width / 2, r.top + r.height / 2);
  return !!(e && e.closest('#目标')); };
```

## 数据补齐会让「写死计数」的断言集体变红（v24）

给血缘补一条 `from`（受试者 → 样本源）后，4 条断言同时红 —— 它们把边数写成 5 / 3 / 0。
全部换成结构不变式：

```
edges == nodes - 1      # 每个非根节点恰有一个父 → 树连通
```

数字型断言的适用边界是「这个数字是设计契约」，不是「这个数字此刻恰好是这样」。
后者一律换成不变式（同 §布局改版：绑现算值 or 写结构不变式）。

## 配色类改动的两条判据（v25）

**① 「有底色」不等于「看得见」。**
`#sampKpis` 第一版条底取 `#F1F7FD` —— 计算色、DOM、断言全都正常，但与页面底
`--color-paper: #F5F8FC` 只差 **1.4% 亮度**，屏幕上仍是一条白带。
判据必须是**与页面底的亮度比**（≥ 1.10），而页面底要从 token 现算（临时元素 + `var(--color-paper)`），
不许把 `#F5F8FC` 抄进断言。
同类：**相邻两层还必须有明确的明暗方向**（这里定的是「条深格浅」：条底亮度 0.8274，四格 0.851~0.883）——
反过来会让同色相的那一格陷进底里，而几何与 DOM 一点毛病没有。

⚠ **方向不能用 `ratio()` 判**：它算的是 `(max+.05)/(min+.05)`，**恒 ≥ 1**，
写成 `> 1.0` 的断言永远通过 —— 层次真的做反了照样是绿的（v25 第一版就是这么写的）。
带方向的判据必须比**亮度本身**（探针里 `lumOf()` 单独返回 `wrapL` / 每格 `L`），
并要求差值 ≥ 0.02，光「不等于」不够。写完一条 `need()` 先问一句：
「有没有可能让实现做反还能通过？」

**② 「参考某处配色」不等于「把色号抄过来」。**
血缘顶栏那四个色是**配白底**的（白字压顶栏 / 深字压白卡身），搬到浅色底上当文字色会掉到
4.1:1（青 `#14808F` 在 `#E6F3F4` 上）。搬配色要连「它原来配谁」一起搬，落地前按**新底**重算，
不够就取同色相更深的一档。

**③ 配色评估用「多候选一次出图」的探针，不要改一次跑一轮全量。**
`改 CSS → build → verify（几分钟）→ 看图` 一轮只看得到一个方案。写个临时探针：
注入 `<style>` 改目标属性、`Page.captureScreenshot` 带 `clip`（放大 2 倍）拍同一个组件、
几张拼成竖列对照图，一次看完再定。探针写在 `/tmp`，**不进仓库**。

**④ 改共用组件前先问「还有谁在用」。**
`.mrow` / `.mcell` 是全站指标条（项目详情、抽屉、基因 tab 都用），配色只能挂到实例 id 上。
并且要**专门拍一张「同页但没被改到的那处」**（`49-samp-kpi.png` vs `34-gene-tab.png`）——
否则没有证据能说明改的是这个实例而不是整个组件。

## 搬家的改动要复查三类「静默放宽」的检查（v26）

把样本详情五块从页面搬进右侧抽屉后，**没有任何断言主动变红**，但有三类检查
悄悄量不到目标了 —— 它们不报错，只是**少量了**：

| 检查 | 退化表现 | 修法 |
|---|---|---|
| 表格居中探针 | 抽屉收起时里面的表 `display:none` 被跳过：表数 6→4、列数 38→24 | 量之前先 `__sampDrawer(true)` 把抽屉滑出来 |
| 截图 | setup 里 `scrollIntoView` 只滚抽屉内部、页面仍停在顶部 → 拍成「列表 + 空白」 | 先用 `__sampPick()` 让抽屉自动滑出，再滚目标 |
| 命中测试 | 元素在屏幕外 → 一律 `(null)`，看着像控件坏了 | 同上 + `hitOK2()` 自带 `scrollIntoView` |

判据：**凡「元素换了住处」的改动**，都要问一句「原来量它的那些探针，现在还够得着吗」。

## 滑入式抽屉的第三态（v26 · 真事故）

`hidden` 与 `is-open` 是**两个状态位**，组合出三种姿态：

| 姿态 | `hidden` | `.is-open` | 屏幕上 |
|---|:---:|:---:|---|
| 收起 | `true` | 无 | 不在 |
| **幽灵** | `false` | 无 | **在屏幕外**（`translateX(100%)`） |
| 打开 | `false` | 有 | 在 |

关闭 = 先摘 `is-open` 播 0.26s 动画、**300ms 后**才 `hidden`。若 `openDrawer()` 写
「`!hidden` 就提前返回」，在「关上后 300ms 内又打开」的路径上 `is-open` 再也加不回来 ——
幽灵态下高度、DOM、`hidden` 全正常，**只有 `elementFromPoint` 返回 `null`**。
修法：先 `clearTimeout(T)` 撤销收尾，提前返回的条件是 `was && is-open`；
「开着」的定义也改成 `!hidden && is-open`。

探针：`__drawer(true/false)`；必测路径 —— **开 → 关 → 300ms 内再开 → 命中测试**。

## 叠放抽屉的「盖住」要判几何，不是判命中（v26）

二级抽屉盖上后，**下层被盖住的按钮点不到是正确行为** —— 别写成
「按钮仍可命中」的断言（实测 elementFromPoint 返回上层的 TD，判红）。
正确判据是**几何覆盖**：下层按钮中心 ∈ 上层 `getBoundingClientRect()`。

同族教训：浮层的 z-index 断言不能只查 `>= 60` 这种下限 ——
两个抽屉同为 61 时谁盖谁由 DOM 顺序决定，**必须断言「上层 z > 下层 z」**
（这里是 `projZ == 62 && sampZ == 61`），再加双向命中：上层关闭按钮接得住、
下层按钮被盖住。

另：整数（clientHeight）与浮点（getBoundingClientRect）做 `==` 会挂在
小数差（278 vs 278.477），一律容差 `< 1`。

## 撤除 UI 元素会戳穿「被它遮住」的隐藏依赖（v27）

撤候选 chips（12 个 + 「还有 N 例」）后暴露两处被遮的问题：
① `sampFltReset()` 固定回第 1 页不回定位 —— chips 时代「当前项置顶」一直
   保证选中项可见，撤掉后「重置筛选」= 选中高亮凭空消失（真 UX bug）。
② 验证脚本 `q('[data-samp-pick="S037"]')` 的首个匹配从「永远存在的 chip」
   变成「页码相关的列表行」—— 页码不对就是 null。
判据：**撤任何 UI 元素前，先问「哪些逻辑 / 断言在借它的副产品」**；
撤完后跑一遍全量，null / 计数类失败先查「是不是有个隐藏依赖没了」。

另：空态列表 tbody 本来就渲染一行「暂无数据」占位 —— 判空用
「`.sampid` 数 == 0」，不是 `rows == 0`。

## verify 跑不动：Chrome 更新器被沙箱拦截（v27 · 环境问题）

症状：验证稳定跑 2 分 02 秒即断、日志 0 字节，stderr 是
`[sandbox] 拦截 ~/Library/.../GoogleUpdater/... (file-delete)`。
根因：chrome 启动会拉起内置的 Omaha 更新器（`--wake` / 自更新清理），
它删的是**真实家目录**（`$HOME` 重定向无效，macOS Chrome 不认），
`--disable-component-update` / `--check-for-update-interval` 也管不住心跳。
修法：verify.py 这类长跑命令要用**无沙箱模式**执行（工具的
dangerouslyDisableSandbox，需用户授权）。chrome 参数里保留
`--disable-component-update --disable-background-networking --no-first-run`。
排查口诀：日志 0 字节 + 稳定卡同一时间点 → 先怀疑沙箱拦截环境进程，
`tail /tmp/cdp_verify.log` 看 chrome 自己走到哪。
